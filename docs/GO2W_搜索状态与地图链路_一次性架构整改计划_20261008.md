# Go2-W 搜索状态与地图链路一次性架构整改计划

版本：2026-10-08。执行对象：能够修改本仓库代码的 AI。目标是一次提交完成搜索图、Web 状态、三维物体叠画、事件推送和重复接口的收敛；完成后运行离线验收并给出结果。请直接按本文修改代码，不再输出另一份泛泛的设计方案。

## 0. 先读的事实与边界

1. 先读 [实际功能接口审计](GO2W_实际功能接口与架构审计_20261008.md)，然后核对当前工作区。用户已有未提交改动；只修改本计划涉及的文件，不重置、不覆盖其他工作。
2. 生产 Web 搜索链是 `SearchSessionService → SubprocessSearchExecutor → autonomous_search_worker → run_go2w → AutonomousExplorer → Nav2SearchBackend`。`--backend nav2` 的 CLI 分派已修好，不要重新引入离线 mock 分派。
3. **修正上次审计中的地图入口描述**：`start_autonomous_search_web.sh` 实际启动 `plain_slam_web_bridge.py` 写自主搜索的 `slam_map_3d.json`；`start_manual_web_demo.sh` 和 `start_remote_control_mapping.sh` 才启动 `webui_map_snapshot_writer.py`。两者工作模式不同，整改时必须分别接线。任何一个模式不能出现两个进程同时写同一张地图 JSON。
4. `/go2w/motion` Action、`/go2w/arm`、急停、控制权、Nav2 `localization_valid`、碰撞监视、唯一 odom publisher 等是实体安全边界。简化 Web 数据链时保持这些门禁的现有行为。此次验收不向机器人发送运动命令。
5. 不增设服务注册表、通用事件框架、第二套地图模型、兼容双写、按 mtime 猜数据源或宽泛 `except Exception: pass`。只保留一种生产写法；离线 mock 是测试替身，不是生产兜底。传感器或地图缺失时明确呈现不可用，不能拿旧数据冒充当前数据。

## 1. 完成后的结构与不变量

| 数据 | 唯一拥有者 | 跨进程形式 | Web 读口 |
| --- | --- | --- | --- |
| 搜索会话、控制权、启停 | `SearchSessionService` | worker JSONL 命令 | `/api/search/state`、`/ws/search` |
| 持久对象身份、Place、Frontier、关系 | worker 中现有 `SemanticNavigationGraph`，其 `SemanticObjectMap` 管对象 ID | **图版本改变时**一份完整 `graph_snapshot` IPC | `state.graph`；历史同一份图 |
| 普通进度、决策、运动结果 | 现有 `SearchEvent` | 小事件 JSONL，不附完整图 | `/ws/search` 和 `state` |
| 固定世界点云、轨迹、地图健康 | 当前模式的唯一 ROS 地图桥 | 原子 `slam_map_3d.json`；不读搜索日志 | `/api/slam/map3d` |
| 三维待显示对象 | 当前模式的 `SemanticObjectMap` | 原子 `semantic_objects.json`；包含地图会话标识 | `/api/slam/map3d` 合成结果 |
| 网页历史 | `SearchSessionArchive` | 小状态 JSON + 图 JSON + 追加事件 JSONL | `/api/search/history*` |

不可违反的条件：

- 同一搜索 session 的 Web 状态只有一份 `graph`；对象、Place、Frontier、拓扑均从它读取。`map.semantic_navigation_graph`、`spatial.spatial_map`、`spatial.semantic_graph` 不再持有该图的副本。
- 一次语义图 revision 最多序列化一次用于 Web IPC；普通 `observation`、`memory_update`、`navigation_result` 不携带完整 `ExplorationGraph` 或完整语义图。历史原始观测仍写入事件日志。
- 三维点云和三维对象只有在 `map_epoch`、`frame_id` **同时相同**时叠画。地图桥重启或 SLAM reset 后生成新 `map_epoch`，旧对象立即不上屏；等新会话产生对象再显示。不用坐标包围盒或文件修改时间推断“属于同一张地图”。
- `/ws/search` 只传小事件和一次初始状态快照。地图版本事件只给 `revision`；浏览器收到后从 `/api/search/state` 拉取一次新图。WebSocket 断线重连也读取同一状态快照。
- 对外搜索状态只用 `GET /api/search/state`。历史仍用 `GET /api/search/history` 和 `GET /api/search/history/{session_id}`。只读地图仍用 `GET /api/slam/map3d`；控制和急停接口保留原语义。

## 2. 精确数据契约

### 2.1 Worker → Web：图快照与普通事件分开

在现有 worker stdout JSONL 中新增**唯一**内部消息，不创建新网络 API：

```json
{"type":"graph_snapshot","session_id":"search_...","task_id":"...","executor_id":"...","worker_generation":1,"revision":12,"graph":{"schema_version":"semantic_navigation_graph_v1","revision":12,"current_place_id":"P1","places":[],"objects":[],"frontiers":[],"edges":[],"object_topology":{}}}
```

`graph` 使用现有 `SemanticNavigationGraph.to_dict()` 的语义，但 Web 投影只保留 `places`、`objects`、`frontiers`、`edges`、`current_place_id`、`object_topology`、`revision` 和地图渲染确实使用的字段。`observations` 是离线证据，`nodes` 与前三个数组内容重复，二者不进 Web 图；前端地图直接从这三个数组绘制。投影只写在 `SemanticNavigationGraph` 的一个明确方法中，例如 `web_snapshot()`；不要在 worker、adapter 和 JS 各自再造一套图字段映射。原始完整图可以在会话结束时继续作为离线 artifact 写一次。

图消息按同一 session 的 `revision` 严格递增。worker 在 explorer 回调中检测 revision，变化时**先**发 `graph_snapshot`，再发导致变化的普通事件。初次进入会话时发一次 revision 0 或第一次有效图；目标在首帧就确认的路径也必须发确认后的最终图。`session_id/executor_id/worker_generation` 继续使用现有匹配门，旧 worker 的消息不能覆盖新会话。

Web 接收图后更新唯一 `state.graph`，再向 bus 发布轻量的 `MAP_UPDATED`：

```json
{"event_type":"MAP_UPDATED","payload":{"revision":12}}
```

这里的 `MAP_UPDATED` 是客户端刷新通知，不再携带图。决定、告警、终止、动作结果仍用现有 `SearchEvent` 类型。不要把完整图放进 `SearchEventBus.recent`、`webui_events.jsonl` 或浏览器 WebSocket 增量。

`SearchEventHub` 的跨线程入口改为容量固定为 256 的 `queue.Queue`。executor 读线程只做 `put_nowait`；ASGI loop 每 50 ms 批量取出后广播。队列满时清掉该批待发增量，标记需要重同步，下一轮向所有连接发送当前 `/api/search/state` 的同形快照；归档和 store 更新在入队前完成，因而这一步不会丢事实。同一批消息向各 socket 并发发送，每个发送设置 1 秒超时，超时即断开该慢连接；上一批发送结束后才处理下一批，不创建无限累积的发送任务。新连接先发送当前状态快照，再接收后续增量；将注册连接与首个快照串行化，保证增量不在首个快照之前到达。删除连接时另发最近 200 个事件的旧回放消息；历史详情由历史 API 读取，终止后状态快照始终以 store 为准。

### 2.2 Web 状态与归档

`GET /api/search/state` 返回当前小状态加**一份** `graph` 和 `graph_revision`。`state.spatial` 保留 RGB-D、位姿、健康等真正独立的空间数据；删除从图重复生成的 `spatial.semantic_graph/spatial_map/place_graph/semantic_objects/frontiers`。旧 `state.map` 删除，地图渲染直接读 `state.graph`。

每个新 Web 会话归档采用：

```text
outputs/live_runs/<session_id>/
  webui_session.json       # 会话索引；开始、状态变化、结束时更新
  webui_state.json         # 不含 graph 的小状态；普通事件变化时更新
  webui_graph.json         # 唯一图快照；graph revision 变化时更新
  webui_events.jsonl       # 追加小事件；绝不内嵌完整图
  events.jsonl             # 现有 worker 原始运行证据，保留
```

写图文件用已有的临时文件加 `os.replace`。Web 进程恢复时读取小状态和图文件各一次，合成 `/api/search/state` 与历史详情；不要在运行时维护两套归档格式。已有 v1 归档须做**一次性迁移**：提取旧 `webui_state.json` 中的语义图到 `webui_graph.json`，从状态里删重复图字段；原始归档先备份，迁移完成后运行时代码只读新格式。迁移脚本可以留在 `scripts/go2w/` 供现场执行，但不要在每次启动时静默兼容或自动迁移。

### 2.3 ROS 地图与物体快照

两种现有地图桥各负责其模式的 ROS 输入与健康判据，**输出同一份 Web 地图契约**：

```json
{"schema_version":"go2w_slam_web_cloud_v2","map_epoch":"随机且本次地图会话稳定的ID","frame_id":"pslam_map","map_revision":7,"generated_at":0,"points":[],"mapping_health":"..."}
```

地图桥在进程启动时创建新的 `map_epoch`，同一进程内地图 reset 时再换一次；桥重启即新 epoch，即使旧点云仍存在也不复用其对象。两种桥已有各自的 `mapping_session_id`：自主桥在 reset marker 时递增，手动/遥控桥在 LIO 日志截断时递增；把进程启动时的一段随机前缀与该计数拼成 epoch，避免再造第二套 reset 状态。它还原子写一份**不含点云**的 `slam_map_meta.json`：`map_epoch`、`frame_id`、`map_revision`、`generated_at`。对象生产者只读这份轻量元数据，不反复解析几万点的大地图 JSON。地图桥自己继续维护原有真实健康判据、点云过滤和冻结逻辑；不要用对象快照反推地图健康。

当前模式的对象生产者直接从其内存中的 `SemanticObjectMap` 取实体，不扫描 `events.jsonl`：

```json
{"schema_version":"semantic_object_display_v1","map_epoch":"同一ID","frame_id":"pslam_map","producer_session_id":"search_...","graph_revision":12,"objects":[],"object_filter_stats":{"input":0,"displayed":0,"filtered":0,"dropped":{}}}
```

自主搜索由现有 `AutonomousExplorer.semantic_graph.object_map` 写；实体遥控建图由 `remote_control_semantic_mapping_worker.py` 的 `self._semantic_map` 写。两处只调用同一个纯函数，把 `SemanticObjectEntry.to_dict()` 经现有 `normalize_snapshot_object` 和 `select_display_objects` 转成显示对象；**显示门只保留这一份实现**。每次持久对象版本变化时原子覆写 `semantic_objects.json`；无合法 `map_epoch` 的对象不写成当前地图对象。原始逐帧检测继续保存在 `events.jsonl`，用于取证和离线评测，不参与在线显示选源。

`GET /api/slam/map3d` 在 Web 层读取地图快照与当前模式**显式配置路径**的对象快照。仅当两个标识相等时合成 `objects` 和 `object_filter_stats`，否则返回空 `objects`，并以 `object_overlay_status` 告知 `NO_OBJECT_SNAPSHOT`、`FRAME_MISMATCH` 或 `MAP_EPOCH_MISMATCH`。`/api/slam/map3d` 仍是前端唯一三维接口；无需新 `/api/objects3d`。手动演示如果没有语义建图进程，就显示地图而不显示历史 Dataset D 物体。

地图 Web 读口按文件 `mtime_ns` 缓存已解析点云；每次 HTTP 请求只重算年龄、状态等少量时间字段。三维 JS 按当前模式地图快照的实际更新周期轮询：普通自主模式可用 1–2 秒，实体遥控建图保持其现有 1 秒级刷新；避免 850 ms 重复解析同一份大 JSON。不要增添另一个元数据 HTTP 端点或再开一条地图 WebSocket。

### C. 公共接口收口

保留：`/api/search/state`、`/api/search/readiness`、`/api/search/history`、`/api/search/history/{id}`、`/ws/search`、`/api/slam/map3d`、现有搜索控制 POST、手动控制/急停接口。删除当前前端不用且完全从 `state` 重复投影的 `GET /api/search/map`、`/place-graph`、`/frontiers`、`/semantic-map`、`/objects`、`/decisions`、`/history/decisions`、`/events`、`/executor`。仓库内所有测试和文档改为新读口，不能留下同义兼容路由。

`SearchStartRequest` 对生产 Web 固定 `backend=nav2`、`spatial_provider=plain_slam` 和 RGB-D/空间探索配置；请求只表达任务、预算、检测模式、干跑/运动授权。请求模型不再提供 `reasoner` 选择，生成 worker 命令时固定传现有 CLI 名称 `semantic_navigation`（当前 `SearchStartRequest` 内部值 `semantic` 仅是别名）。删除 `rtabmap`、旧 reasoner 别名、重复的 `operator_supervised` 计算与并无消费者的配置项。离线 mock 通过测试直接注入 `InProcessMockExecutor`，不通过生产 HTTP 参数伪装真机任务。CLI 的离线诊断选项可继续留在 CLI，不能倒灌到生产 Web 请求模型。配置读取错误显式报错，不静默改回另一套默认值。

具体修改 `app/manual_web_demo/search_models.py` 的 `SearchStartRequest.from_dict()` 与 `validate()`，以及 `search_session_service.py` 中生成 worker 命令的字段映射；删字段时同时清理 `search_ui.js` 的请求体、`app/manual_web_demo/config.py` 的无效默认值与对应测试。生产请求的运动授权字段必须继续显式传递到既有安全门。

## 4. 实施顺序：一次完成，不留双轨代码

1. 先把 §2 的数据形状写在相关现有模块的 docstring，并从当前 `rg` 调用点确认旧图字段、旧路由、两种地图启动入口。记录本次改动前的工作区状态；保留用户未提交文件。
2. 先改 worker 图发送、executor 透传、service/store 单图字段和 archive；同一批提交里改前端图消费。新旧图链不要同时长期运行，也不要让 adapter 在新消息之外额外生成旧全图事件。
3. 接着改对象内存快照和两个地图桥，再改 `/api/slam/map3d` 合成及三个启动脚本。把遥控建图只读显示与自主搜索分别跑通离线 fixture；两者不能互相 glob 对方的事件日志。
4. 最后删重复路由、兼容字段与不再有调用点的函数/参数；执行一次性归档迁移；更新 README 里真正对外的接口列表和运行说明。
5. 全部修改、迁移、测试完成后才交付。最终回复列出改动文件、被删除的接口、测试结果、旧档案迁移结果、尚未做的真机动态验收。不要以“规划完成”代替代码完成。

## 5. 必须通过的验收

### 离线行为

- Mock Web 搜索：start → 观测 → 图更新 → 暂停/恢复 → 终止；`GET /api/search/state` 始终只有一份图，图 revision 递增，Place/对象/Frontier 和对象拓扑与 worker 同 revision。首帧目标确认仍有最终图。
- worker 发 100 个普通事件而图 revision 不变时：`graph_snapshot` 为 0 条、`webui_graph.json` 重写 0 次；revision 增加一次时各恰好 1 次。`webui_events.jsonl` 与 WS 增量不含 `nodes/places/objects/frontiers` 全图数组。
- Web 重启后从小状态与图文件恢复，历史详情、目标结果、决策、对象拓扑和地图 revision 与重启前一致。旧 v1 会话经一次性迁移后可读；运行时只有一种读法。
- 两个不同 `map_epoch` 但相同 `frame_id` 的快照组合返回空对象；同 epoch 同 frame 才显示，且保留现有 `label_zh`、目标标记、置信度门、合法 box 尺寸和过滤统计。遥控建图与自主搜索各自使用其当前会话对象；没有对象源时地图仍可看，但不显示旧档案物体。
- 搜索 hub 从 executor 读线程并发发布时不丢唤醒；队列有固定上限，慢浏览器不会阻住其他连接。队列溢出时给所有连接最新 state 重新同步；终止状态不能因旧事件覆盖。历史事件始终落在 archive 中，不以 WS 是否在线决定是否保存。
- `GET /api/slam/map3d` 连续多次请求而地图文件不变时只解析一次点云 JSON；地图 revision 改变后返回新点云。三维 JS 不再 850 ms 请求一份没变化的大地图。

## 6. 简化规则与禁止事项

- 只有两个数据处理边界：**worker 产事实，Web 展示/归档事实**。对象投影一次，图投影一次。不要把每个字段拆成独立 provider、service、adapter。
- 只在进程边界、文件落盘和对外输入处处理明确错误；不写宽泛异常吞没、虚构默认传感器值、跨历史 session 选最新文件、过期坐标自动回退。
- 三维对象显示门与持久对象入口门判的是不同问题，保留两个现有判据；不要把“少写代码”误解为删除质量门。急停、租约和运动门同理。
- 真机安全验收按现有启动脚本和人工监督进行；本计划的代码验收只到**可部署、可离线验证**。没有现场控制人与实体急停时，不触发 `--enable-motion`、不发速度、转向或姿态命令。
