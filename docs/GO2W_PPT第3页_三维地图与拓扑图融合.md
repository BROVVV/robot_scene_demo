# 第 3 页｜三维地图与拓扑图融合：构建统一语义导航图

> 本文件只对应一张 PPT 内容页。页面主体保持简洁，算法细节和讲稿放在备注中。

## 一、页面核心结论

以机器人位姿和 Place 节点作为连接桥梁，将三维地图中的几何位置、可通行区域和探索边界，与拓扑图中的地点连接、物体语义和访问记忆融合为统一的 SemanticNavigationGraph。

融合后，任务 Agent 可以同时回答：

- 空间上能不能到达？
- 应该优先前往哪个地点？
- 目标可能位于哪些物体或区域附近？
- 哪条路线的信息增益更高、代价更低？

                 │   │                       │      │

                 │   │                       │      │

### 中央融合层旁边放 4 个算法标签

1. **统一坐标**
   - camera → base_link → map/odom
   - 所有位姿携带坐标系、来源和空间质量等级。

2. **Place 锚定**
   - 连续三维位姿聚合为稳定地点节点。
   - 原地转动更新方向覆盖，不重复创建地点。

3. **语义挂载**
   - 三维物体通过 OBSERVED_FROM 连接到观测地点。
   - 跨帧物体关系转换为持久语义边。

4. **双层规划**
   - 拓扑图负责选择区域和规划全局地点序列。
   - 三维地图负责距离、Frontier、净空和局部可执行性。

### 页面底部结论句

> **统一图同时保留三维空间的几何约束和拓扑图的任务语义，使任务 Agent 获得“去哪里、为什么去、是否可达”的完整依据。**

## 三、算法设计备注

### 1. 坐标对齐：让两张图具有共同空间基准

三维物体从相机坐标系转换到地图坐标系：

\[
\mathbf p_{map}
=
T_{map\leftarrow base}
T_{base\leftarrow camera}
\mathbf p_{camera}
\]

- 优先使用 TF2 完成 map ← camera 的坐标变换。
- TF2 不可用时，使用相机外参与机器人平面位姿进行相对变换。
- 每个结果保留 frame_id、transform_source 和 spatial_quality。
- 坐标系不一致时拒绝直接融合，避免将不同世界坐标中的位置错误叠加。
- 只有质量满足要求的数据才参与米制距离、路径长度和净空判断。

### 2. Place 锚定：用稳定地点连接几何地图和拓扑图

将当前位姿 \(\mathbf p_t\) 与已有 Place 中心 \(\boldsymbol\mu_i\) 做最近邻关联：

\[
i^*=\arg\min_i\|\mathbf p_t-\boldsymbol\mu_i\|_2
\]

~~~text
平移量 < d_move
    → 保留当前 Place，只更新观测方向与语义

平移量 ≥ d_move，且最近 Place 距离 ≤ r_merge
    → 复用已有 Place，形成重访或闭环

平移量 ≥ d_move，且没有邻近 Place
    → 创建新 Place，并增加 CONNECTED_TO 边
~~~

代码默认参数：

- 最小有效平移量：\(d_{move}=0.10\,m\)
- Place 合并半径：\(r_{merge}=0.60\,m\)

Place 因此成为两类地图的公共索引：它既保存真实空间位姿，也保存观察过的方向、物体、负证据与访问历史。

### 3. 语义挂载：将三维实体接入拓扑位置

每次观测执行三步关联：

1. 根据机器人位姿确定本次观测所属 Place。
2. 将帧内目标经过三维定位和跨帧关联，转换为稳定 Object。
3. 建立 Place、Object、Frontier 之间的结构化边。

| 起点 | 关系 | 终点 | 决策含义 |
|---|---|---|---|
| Place | CONNECTED_TO | Place | 地点之间存在移动连接 |
| Place | OBSERVED_FROM | Object | 该物体曾从此地点被观测 |
| Place | FRONTIER_TO | Frontier | 可从该地点继续探索此边界 |
| Object | NEAR、LEFT_OF 等 | Object | 物体之间存在空间语义关系 |

不同时间和不同朝向看到的物体都能通过同一 Place 汇入持续世界模型，形成跨帧、跨视角的语义拓扑。

### 4. Frontier 融合：同时利用几何未知区域和拓扑覆盖

三维占据地图从 Free–Unknown 边界提取米制 Frontier，提供：

- 地图坐标、相对方位和距离。
- Frontier 规模与空间信息增益。
- 可达性、地图版本和数据来源。

拓扑图为候选补充：

- 所属或邻近的 Place。
- 当前地点的方向覆盖情况。
- 目标语义相关性和历史负证据。
- 路线访问次数、失败次数与阻塞状态。

米制地图暂不可用时，系统可用 Place 的未观测航向生成拓扑 Frontier；该候选只表达探索方向，不生成没有依据的精确距离。

### 5. 联合评分：把几何价值与任务价值合成一个排序

\[
S(f)=
w_sS_{semantic}
+w_iG_{information}
+w_nS_{novelty}
+w_mS_{memory}
-w_rC_{route}
-w_vP_{visited}
-w_fP_{failure}
-w_eP_{negative}
\]

- \(S_{semantic}\)：候选区域与目标语义的相关性。
- \(G_{information}\)：三维地图估计的空间信息增益。
- \(S_{novelty}\)：未探索程度。
- \(S_{memory}\)：知识库和历史观测提供的先验。
- \(C_{route}\)：拓扑路径或米制距离代价。
- \(P_{visited}\)：重复访问惩罚。
- \(P_{failure}\)：历史通行失败惩罚。
- \(P_{negative}\)：该区域已有有效负证据的惩罚。

该评分把“空间上值得探索”和“任务上值得探索”统一到同一个候选排序中。

### 6. 分层规划：拓扑选路，三维地图校验局部执行

~~~text
任务 Agent 选择目标 Place / Object / Frontier
                    ↓
PlaceGraph 上执行 Dijkstra，获得全局地点序列
                    ↓
三维地图检查目标坐标、距离、局部净空与可达性
                    ↓
生成第一个可执行的局部目标
                    ↓
成功或失败结果回写 CONNECTED_TO 边
~~~

拓扑边代价包含距离与失败历史：

\[
C_{ij}
=
d_{ij}
+2N^{fail}_{ij}
+3\cdot\mathbb I(status=DEGRADED)
\]

- BLOCKED 边不进入当前路径搜索。
- 通行成功会提高边的可通行置信度。
- 连续失败会增加边代价或将其标记为阻塞。
- 下一轮规划自动选择其他路线或 Frontier。

## 四、建议使用的真实素材

一页中放三张互相对应的图：

1. **左侧：三维地图**
   - 显示点云或占据栅格。
   - 标出机器人位姿、障碍物、未知区域和一个 Frontier。

2. **中间：统一语义导航图**
   - 蓝色 Place、绿色 Object、橙色 Frontier。
   - 标出 CONNECTED_TO、OBSERVED_FROM、FRONTIER_TO。

3. **右侧：联合决策结果**
   - 高亮被选中的目标 Place 和 Frontier。
   - 显示拓扑路径、局部三维目标及候选评分。

同一个实体在三张图中保持相同颜色，让听众立即看懂“三维位置 → 拓扑节点 → 决策目标”的映射关系。

## 五、推荐的 90 秒讲稿

“这一页主要介绍我们如何把已有的三维地图和拓扑图真正连接起来。三维地图提供精确的位置、障碍物、未知区域和探索边界；拓扑图保存地点之间的连接、访问历史以及每个地点观察到的语义物体。

融合时，首先把相机观测、机器人位姿和地图统一到同一坐标系，并为每项数据保留坐标来源和质量等级。随后把连续位姿聚合为稳定的 Place 节点：原地旋转只更新当前地点的观察方向，发生真实位移才创建或重访另一个 Place。

视觉检测到的三维物体挂载到对应 Place 上，地点之间使用 CONNECTED_TO 连接，物体与地点使用 OBSERVED_FROM 连接，未知区域使用 Frontier 表示。这样就形成一张同时包含位置、物体、关系和探索边界的统一语义导航图。

规划时，任务 Agent 结合语义相关性、信息增益、路径代价和历史失败选择目标区域，再在拓扑图上求全局路线，并由三维地图检查局部距离和可通行性。执行结果还会反向更新拓扑边。最终得到的不是一个孤立方向，而是一个同时具有空间依据、语义依据和路线依据的下一步决策。”

## 六、这一页需要突出的技术价值

- **统一空间基准**：三维坐标、机器人位姿、物体和拓扑节点可以相互查询。
- **稳定空间锚点**：Place 将不同视角的物体观测组织成持续世界模型。
- **几何与语义联合规划**：同时考虑可通行性、信息增益和任务相关性。
- **支持闭环与重访**：回到已有位置时复用 Place，并更新语义与方向覆盖。
- **质量感知降级**：米制信息不足时保留拓扑方向，但不虚构精确距离。
- **路线质量持续更新**：成功、失败与阻塞状态会改变边代价并影响下一次规划。
