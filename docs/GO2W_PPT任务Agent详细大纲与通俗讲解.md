# GO2W 任务 Agent 详细大纲与通俗讲解

> 建议作为 PPT 中“任务 Agent”这一页的替换内容。  
> 页面展示控制在一页，算法细节和例子放入演讲备注。  
> 核心定位：任务 Agent 不是一个直接控制机器狗的聊天模型，而是一个围绕任务目标持续执行“汇集信息—形成判断—输出偏好—接收反馈—重新规划”的确定性管理层。

---

## 一、PPT 页面标题

**任务 Agent：汇集多源证据，形成可执行、可追溯的下一步判断**

### 页面核心结论

任务 Agent 将任务要求、视觉场景、知识库、空间拓扑、历史记忆和安全状态装配成统一决策上下文，再调用目标图匹配与候选方向排序，输出带完整依据的 SearchDirective；下游执行结果继续回流，驱动下一轮判断。

---

## 二、建议直接放在 PPT 上的主体结构

### 1. 页面中央：Agent 决策闭环

~~~text
用户任务
  ↓
任务结构化
目标 + 属性 + 关系 + 约束 + 子任务
  ↓
┌────────────── 决策上下文装配 ──────────────┐
│ GoalGraph        ：目标应该长什么样、与谁有关 │
│ SceneGraph       ：当前画面实际看到了什么      │
│ Knowledge        ：目标通常可能在哪里          │
│ Topology         ：当前在哪、哪些地方去过       │
│ Memory           ：哪些方向看过、哪里已有负证据 │
│ Robot / Safety   ：当前朝向、能力和安全边界      │
└──────────────────┬─────────────────────────┘
                   ↓
         目标图匹配 + 候选方向排序
                   ↓
 SearchDirective：下一步观察偏好 + 证据 + 不确定性
                   ↓
       下游规划器 / 安全门控 / 离线动作记录
                   ↓
       新观测与执行结果回流，触发下一轮重规划
                   └───────────────────────↺
~~~

### 2. 页面右侧：为什么它叫 Agent

- **有持续目标**：始终围绕完整任务，而不是只回答当前一句话。
- **有任务计划**：维护任务阶段、当前子任务、依赖和结束条件。
- **会主动取信息**：信息不足时选择能减少不确定性的观察方向。
- **有状态与记忆**：保留已观察方向、负证据、访问地点和失败历史。
- **会根据反馈重规划**：新证据、失败或缺失信息都会改变下一步。
- **有能力边界**：只给搜索偏好，不确认目标、不授权运动、不绕过安全检查。
- **全过程可审计**：每个候选为什么入选或淘汰，都写入 DecisionTrace。

### 3. 页面底部：Agent 与普通问答 AI 的区别

| 普通问答 AI | 任务 Agent |
|---|---|
| 输入一个问题，输出一段回答 | 接收目标，持续维护任务状态 |
| 主要依赖当前提示词 | 汇集视觉、知识、地图、记忆和安全信息 |
| 回答结束即完成 | 观察、判断、反馈、重规划形成闭环 |
| 通常输出自然语言 | 输出结构化指令、候选排名和证据引用 |
| 不一定知道结果是否真的执行 | 跟踪建议是否被下游采纳以及执行结果 |

### 页面底部强调句

> **Agent 的关键不在于“说得像人在思考”，而在于它能围绕目标持续感知环境、维护状态、选择行动、检查结果并重新规划。**

## 三、各种信息是怎样汇集起来的

### 信息源 1：任务上下文

任务首先被转换成 SearchTaskContext：

- 用户原始指令。
- 标准化目标名称。
- 目标类别与外观属性。
- 目标和参考物之间的空间关系。
- 任务约束。
- 子任务、依赖关系和可执行性。

例如：

~~~text
原始任务：寻找饮水机旁边的蓝色垃圾桶

标准化结果：
目标      = 垃圾桶
属性      = 蓝色
空间关系  = near
参考物    = 饮水机
当前能力  = 搜索与观察
~~~

Agent 据此建立总体计划：

1. 理解任务。
2. 汇总上下文。
3. 选择搜索方向。
4. 等待视觉复核。
5. 汇报任务结果。

复杂任务存在多个子任务时，Agent 保留原始顺序和依赖，只将当前可执行、且与搜索目标对应的一个子任务标记为 active；需要抓取或物理接触的任务会明确标记为当前执行器不支持。

### 信息源 2：GoalGraph——“我要找什么”

任务被表达成目标图：

~~~text
[蓝色垃圾桶]
      │ near
      ▼
   [饮水机]
~~~

目标图中包含：

- Target：真正要找的目标。
- Anchor：用户明确给出的参考物。
- Context：可用于辅助搜索的场景对象。
- Edge：目标与参考物之间的 near、left_of、inside 等关系。

目标图让系统处理的是“蓝色垃圾桶在饮水机附近”这一完整结构，而不只是识别“垃圾桶”三个字。

### 信息源 3：SceneGraph——“当前真正看到了什么”

多模态视觉将当前观测转换为场景图：

- 当前检测到的物体。
- 物体类别和属性。
- 物体的稳定 ID。
- 物体间空间关系。
- 可用的相对方向及其来源。

系统将 GoalGraph 与 SceneGraph 进行匹配，产生三种状态：

- **ZERO**：目标和有效锚点均未匹配。
- **PARTIAL**：匹配到部分目标结构，需要继续观察。
- **STRONG**：目标图得到较强支持，但仍不能代替视觉确认。

匹配分数由目标、锚点、上下文和关系共同组成：

\[
S_{match}=0.85S_{node}+0.15S_{relation}
\]

节点角色优先级为：

\[
Target:Anchor:Context=0.60:0.30:0.10
\]

这使任务目标始终占主要权重，同时允许参考物和场景关系为搜索提供方向。

### 信息源 4：知识库——“通常可能在哪里”

本地知识库提供目标位置先验，例如：

~~~text
垃圾桶常出现在桌边、墙角或饮水区域附近。
~~~

知识不会直接决定方向。只有当知识提到的相关物体真实出现在当前 SceneGraph 中，并且该物体具有可用方向时，这条知识才能参与候选排序。

~~~text
知识说“垃圾桶常在桌边”
当前画面看到了桌子，并知道桌子在右侧
    → 这条知识可以为右侧候选提供支持

当前画面没有桌子
    → 该知识只显示为 context_only，不参与方向排序
~~~

知识库为空只表示“本轮没有检索到相关知识”，不等于某个方向没有目标，也不能被写成负证据。

### 信息源 5：拓扑图和空间状态——“我在哪里、去过哪里”

Agent 读取只读拓扑摘要和机器人状态：

- 当前 Place。
- Place 数量和连接边数量。
- 当前机器人航向。
- 已观察的方向扇区。
- 距离起点的相对位移。
- 可用的 Frontier 或辅助空间提示。

拓扑信息帮助 Agent 理解搜索进度和空间上下文。拿不到拓扑时记录为 missing_topology_summary，而不是填 0 冒充“当前地图没有节点”。

### 信息源 6：记忆——“哪些地方已经尝试过”

两类记忆共同参与判断：

- **观察记忆**：历史画面、检测对象以及相应观测 ID。
- **负记忆**：在满足有效视觉判据的情况下，某个方向或地点未发现目标。

负记忆会降低重复搜索同一方向的优先级，但模型未运行、画面质量不足或判据没有分辨力时，不能形成负证据。

### 信息源 7：安全与能力边界

Agent 同时知道：

- 当前是否允许前进。
- 是否只允许观察或旋转。
- 当前执行器支持哪些任务。
- 是否缺少地图、图匹配或视觉输入。
- 当前处于 live、offline_replay 还是 test 模式。

任务 Agent 的输出永远不等于运动授权。真正执行前仍需经过下游路径规划、运动边界和安全门控。

## 四、Agent 怎样把信息变成下一步判断

### 第一步：判断是否存在有效锚点

有效锚点必须同时满足：

1. 锚点来自本轮 GoalGraph 与 SceneGraph 的真实匹配。
2. 锚点具有稳定节点 ID。
3. 锚点具有可以转成相对方向的空间信息。

方向还必须注明来源：

- measured：真实测得的相对方向。
- coarse_lr：只根据“左侧或右侧”粗略转换的方向。
- unknown：无法定向，不允许猜测角度。

如果存在有效锚点，Agent 会优先输出“朝锚点方向重新观察”的偏好；如果没有有效锚点，就转入未观测方向探索。

### 第二步：产生可比较的候选方向

当前离散候选为：

\[
A=\{-30^\circ,+30^\circ,-60^\circ,+60^\circ,-90^\circ,+90^\circ\}
\]

每个候选方向都携带：

- 是否已经观察。
- 负记忆惩罚。
- 与目标图证据的夹角。
- 与知识证据的夹角。
- 辅助情境提示。
- 转向幅度。
- 证据引用和淘汰原因。

### 第三步：按证据优先级进行词典序排序

系统没有使用缺乏标定依据的随意加权总分，而是使用词典序排序：

\[
K(a)=
\left(
C_{visited}+P_{negative},
D_{semantic},
D_{knowledge},
-S_{auxiliary},
|\Delta\theta|,
Index
\right)
\]

按照从左到右的优先级，选择最小的排序键：

1. 先避开已经观察且负证据较多的方向。
2. 再选择更靠近目标图证据的方向。
3. 再选择更靠近知识证据的方向。
4. 同分时使用低优先级辅助提示。
5. 最后优先较小转角，并用固定顺序保证结果可复现。

这种排序方式的优点是每个判断都有明确优先级，也能准确说明未选候选究竟输在“已经看过”“负证据更多”“离语义证据更远”还是“转角更大”。

### 第四步：输出结构化 SearchDirective

Agent 最终输出的不是一段自由文本，而是一个结构化偏好：

~~~text
决策类型      = EXPLORE_UNSEEN / INSPECT_ANCHOR / REOBSERVE_SECTOR
建议相对方向  = +30°
置信度        = 0.62
是否允许前进  = false
证据引用      = obj_water_dispenser_03、kb_bin_near_water
原因码        = partial_without_anchor
不确定性      = anchor_direction_unknown
~~~

该指令只表达“下一步优先观察哪里”，不会自行确认目标，也不会直接发送底盘命令。

### 第五步：生成 DecisionTrace

同一轮判断被封装成可审计记录，包含：

- 总体计划和当前子任务。
- 本轮实际收到的输入。
- 缺失的信息源。
- 知识条目是 used 还是 context_only。
- 全部候选方向和真实排序键。
- 最终搜索偏好和证据引用。
- 未选候选的淘汰原因。
- 当前不确定性。
- Agent 建议是否被下游采纳。

WebUI 展示的是这份结构化事实，而不是生成一段无法核验的“思维链故事”。

### 第六步：根据反馈进入下一轮

下游结果可能是：

- Agent 建议被采纳。
- 因局部安全检查失败而未采纳。
- 因导航候选更优而改选其他动作。
- 获得新的视觉证据。
- 形成新的有效负证据。
- 目标进入 POSSIBLE，需要换视角验证。
- 目标满足视觉判据，被独立确认。

这些结果会更新场景、记忆、拓扑和任务状态。Agent 在下一轮重新汇集上下文，而不是机械重复上一轮选择。

## 五、“Agent”的点究竟在哪里

### Agent 不是某一个大模型，而是一套闭环系统

项目中的 Agent 能力来自多个组件共同协作：

| 组件 | Agent 中的职责 |
|---|---|
| SearchTaskContext | 保存长期任务目标、属性、关系和约束 |
| Task Agent | 生成计划、汇总上下文、封装审计记录 |
| GoalGraphBuilder | 把任务转换成可匹配的目标结构 |
| GraphMatcher | 判断当前场景对任务目标支持到什么程度 |
| Semantic Reasoner | 产生候选方向并执行真实排序 |
| Memory / PlaceGraph | 保存已观察方向、负证据和空间历史 |
| Planner / Safety Gate | 将搜索偏好转换为安全的下游动作 |
| SearchStateStore / WebUI | 保存每轮状态、决策和下游采纳结果 |

因此更准确的表达是：

> Task Agent 是任务管理和证据编排中枢；Reasoner 是判断模块；Planner 与安全门控是执行接口；记忆和状态存储使它们形成持续闭环。

### 一个系统被称为 Agent，至少需要五个条件

1. **Goal**：有一个跨多轮持续存在的目标。
2. **State**：知道任务进行到哪一步。
3. **Observation**：能读取外部环境和工具结果。
4. **Action selection**：能根据当前状态选择下一步。
5. **Feedback loop**：会检查结果，并据此继续、重试、换方向或结束。

本项目还额外加入：

- Memory：避免反复探索同一区域。
- Capability boundary：不会把搜索建议伪装成运动授权。
- Audit trace：每个结论都能追溯到输入和算法分量。
- Determinism：同样的输入得到同样的决策，便于离线复现与评估。

## 六、和普通 AI 的本质区别

### 普通问答 AI

可以把普通 AI 理解成一个很聪明的顾问：

~~~text
你给它一句问题
    ↓
它根据当前文本生成一段回答
    ↓
回答结束
~~~

它可能能提出合理建议，但通常不会自动知道：

- 机器人此刻朝向哪里。
- 哪些方向已经观察过。
- 哪条知识真正落到了当前画面里的实体。
- 建议是否被路径规划器接受。
- 动作执行后发生了什么。
- 任务什么时候算真正完成。

### 任务 Agent

任务 Agent 更像一个现场任务主管：

~~~text
接收任务
  ↓
拆解阶段并检查能力
  ↓
询问视觉、地图、知识库和记忆
  ↓
比较所有可选方向
  ↓
提出结构化下一步偏好
  ↓
检查下游是否采纳、环境是否变化
  ↓
更新状态并继续规划，直到满足结束条件
~~~

最大的区别不是语言能力，而是：

> **普通 AI 主要负责回答；Agent 负责围绕目标持续组织信息、选择下一步并根据结果继续工作。**

大模型可以成为 Agent 的一个工具，例如解释复杂场景或提供常识先验；但只有接入目标、状态、记忆、工具和反馈闭环之后，它才成为 Agent 系统的一部分。

## 七、用一个例子把整套过程讲清楚

任务：

> “寻找饮水机旁边的蓝色垃圾桶。”

### 第 1 轮：理解任务

Agent 得到：

- 目标：蓝色垃圾桶。
- 锚点：饮水机。
- 关系：near。
- 当前子任务：搜索目标。
- 结束条件：视觉复核链确认目标。

### 第 2 轮：汇集现场信息

当前视觉只看见一张桌子，没有垃圾桶和饮水机：

- GoalGraph 与 SceneGraph 为 ZERO。
- 知识库中“垃圾桶可能在桌边”可以使用，因为桌子真实出现在画面中。
- 左侧方向已经观察过两次。
- 左侧还有一次有效负证据。
- 右侧方向尚未观察。

Agent 不会因为“知识说垃圾桶在桌边”就宣布找到，而是把桌子的方向作为较弱的搜索证据。

### 第 3 轮：候选排序

假设桌子位于右侧，则候选可能表现为：

| 方向 | 已观察 | 负记忆 | 语义证据 | 知识证据 | 结果 |
|---|---:|---:|---|---|---|
| 左转 30° | 是 | 有 | 无 | 较远 | 淘汰 |
| 右转 30° | 否 | 无 | 无 | 最近 | 选择 |
| 右转 60° | 否 | 无 | 无 | 次近 | 转角更大 |
| 左转 60° | 否 | 无 | 无 | 较远 | 排名靠后 |

Agent 输出：

~~~text
下一步偏好：向右观察 30°
主要依据：该方向未观察，负证据为零，且最接近桌子的知识支持方向
不确定性：尚未看到饮水机；知识只能指导搜索，不能确认目标
~~~

### 第 4 轮：获得新观测并重规划

右转后发现饮水机位于右前方，但仍未确认垃圾桶：

- GoalGraph 与 SceneGraph 进入 PARTIAL。
- 饮水机成为有效锚点。
- Agent 将当前子任务调整为围绕锚点重观测。
- 输出朝饮水机方向观察的偏好。

### 第 5 轮：视觉确认

新视角出现蓝色垃圾桶，且空间关系满足 near：

- 目标证据进入 POSSIBLE 或 PRESENT。
- 视觉复核模块独立检查类别、属性、关系和感知质量。
- 只有全部判据通过后，任务状态才进入完成阶段。

这说明 Agent 管理的是完整任务过程，而不是看到一个相似物体就结束。

## 八、建议的 2 分钟讲稿

“任务 Agent 的核心作用，是把分散在各个模块里的信息汇集成一次完整、可追溯的判断。它首先把用户任务转换成目标、属性、空间关系、约束和子任务。例如寻找饮水机旁边的蓝色垃圾桶，系统会明确目标是蓝色垃圾桶，饮水机是参考锚点，两者需要满足 near 关系。

随后 Agent 会同时读取六类信息：目标图描述要找什么，场景图描述当前看到了什么，知识库提供目标通常可能在哪里，拓扑图说明机器人在哪里以及去过哪里，记忆记录哪些方向已经观察或形成负证据，安全状态则限定当前允许提出什么动作。

这些信息不会被简单拼成一段提示词。目标图首先与场景图进行结构匹配，得到零匹配、部分匹配或强匹配。存在有效锚点时，系统围绕锚点重新观察；没有锚点时，则对多个候选方向进行排序。排序优先避开已经观察和具有负证据的方向，再考虑目标图证据、知识证据、辅助提示和转向幅度。

它之所以叫 Agent，不是因为它会生成一段像人类思考的文字，而是因为它有持续目标、有任务状态、有环境观测、有记忆、能选择下一步，并会根据执行结果重新规划。普通问答 AI 通常是问题进来、答案出去；这个 Agent 则会一直运行在‘观察—判断—行动偏好—反馈—重规划’的闭环中。

同时我们给它设置了明确边界：任务 Agent 只产生搜索偏好，不确认目标、不直接授权运动。真正的目标确认交给视觉判据，真正的动作执行还要经过路径规划和安全门控。每轮判断的输入、候选、证据、淘汰原因和下游是否采纳，都会进入 DecisionTrace 并显示在 WebUI 上。”

## 九、汇报时避免的三种表述

1. 不要说“Agent 自己综合所有信息后直接控制机器狗”。
   - 准确说法：Agent 输出搜索偏好，下游规划和安全系统决定最终动作。

2. 不要说“知识库告诉 Agent 目标一定在哪里”。
   - 准确说法：知识只有与当前可见实体建立联系后，才能作为方向支持。

3. 不要把 WebUI 的说明文字称为完整思维链。
   - 准确说法：WebUI 展示的是结构化决策依据、候选排序和不确定性，可验证且可复现。
