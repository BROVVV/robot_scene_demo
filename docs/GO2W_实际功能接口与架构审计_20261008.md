## 2. 唯一的生产调用链

```text
操作员 / WebUI
  POST /api/search/start
  -> SearchSessionService.start_search
  -> 任务理解 run_task_understanding_pipeline
  -> SubprocessSearchExecutor（stdin/stdout JSONL）
  -> autonomous_search_worker.run_session
  -> run_semantic_exploration.run_go2w
  -> AutonomousExplorer.run
  -> Nav2SearchBackend（ComputePathToPose -> NavigateToPose）
  -> /go2w/search_cmd_vel -> 仲裁/平滑/碰撞监视 -> /go2w/motion

观测侧：D435/RGB-D + LiDAR/SLAM/TF -> Quick VLM / Full Semantic
       -> 深度定位、对象图、地点图、候选目标 -> Explorer 下一轮
展示侧：Explorer 事件 -> ExplorerSearchAdapter -> SearchStateStore
       -> /ws/search 和 /api/search/state
三维展示（自主搜索）：/go2w/slam/map_3d
       -> plain_slam_web_bridge -> slam_map_3d.json -> /api/slam/map3d
三维展示（手动/遥控）：ROS 点云 + events.jsonl
       -> webui_map_snapshot_writer -> slam_map_3d.json -> /api/slam/map3d
```

生产导航启动入口是 `scripts/go2w/start_nav2_autonomous_search.sh`。它复用 `start_autonomous_search_web.sh` 起 WebUI，默认只规划，`--enable-motion` 还要通过 `configs/go2w/navigation_gate.yaml` 及现场安全门。`start_autonomous_search_web.sh` 单独运行只起 WebUI/侧车，代码注释明确它不拉起 Nav2。`start_manual_web_demo.sh` 是手动演示入口。不要把三个启动脚本算成三个自主搜索实现。[入口](../scripts/go2w/start_nav2_autonomous_search.sh)、[Web worker](../scripts/go2w/autonomous_search_worker.py)、[搜索主程序](../scripts/go2w/run_semantic_exploration.py)。

## 6. 架构问题：按数据所有权收敛

### P0：命令行 `nav2` 曾被分派到离线 mock（已修复）

`run_semantic_exploration.py:main` 原来只把 `go2w_experimental` 交给 `run_go2w`，其余全部进入 `_run_offline`，所以直接执行默认 `--backend nav2` 会生成模拟搜索；Web worker 绕过 `main()` 直接调用 `run_go2w`，故两入口同名参数不同义。现已让 `nav2` 和诊断用 `go2w_experimental` 都进入 `run_go2w`，离线选项只进入 `_run_offline`。不触及运动授权；`run_go2w` 原有安全门仍生效。[CLI](../scripts/go2w/run_semantic_exploration.py)、[回归测试](../tests/test_semantic_cli_dispatch.py)。

### P1：一张对象图在多个层次反复完整复制

搜索 worker 在 `observation`、`memory_update`、`navigation_result` 事件附带**完整图**；`ExplorerSearchAdapter._map_events` 再规范化所有节点；`SearchStateStore._on_map_updated` 把图复制到 `map.semantic_navigation_graph`、`spatial.spatial_map`、`spatial.semantic_graph`，并复制对象和 frontier 子集。随后 `SearchStateStore.apply` 每个事件都 `deepcopy` **整个**状态，`SearchSessionArchive.record` 原子重写 `webui_state.json` 和 marker。这里的成本随图和事件数增长，状态每次增长后改写全量，属于确定的序列化/磁盘放大；未做现场性能基准，不给出臆测百分比。[图事件](../app/live_robot/explorer_search_adapter.py)、[状态复制](../app/live_robot/search_state_store.py)、[归档写入](../app/manual_web_demo/search_session_archive.py)。

收敛到两个事实：`SemanticObjectMap/semantic_navigation_graph` 拥有内存图；`SearchEventBus` 只传增量与图版本号。Web 只维护一份规范图快照，`map/place/frontier/object` 均从这一份按需投影；归档按图版本变化写快照，其余事件只追加 JSONL。做到这一点前，不能直接删现有复制，否则历史恢复和 WS 初始快照会断。

### P1：三维地图和搜索对象有第二条事实链

手动演示和遥控建图的 `webui_map_snapshot_writer.py` 从 ROS 收图，再从 `objects_glob` 或 `objects_events` 指向的 `events.jsonl` 挑选对象，整份写 `slam_map_3d.json`；writer 使用增量日志读器，并非每轮整读日志。**自主搜索实际使用 `plain_slam_web_bridge.py`，它只写点云、轨迹和健康状态，不读取搜索对象**，因此该模式的三维地图与搜索页面对象状态脱节。Web 每次请求读整份地图 JSON，三维前端每 850 ms 请求一次。两种模式的实际问题分别是日志选源可能串会话，以及自主搜索没有直接使用当前对象图；共同问题是点云 JSON 全量传输与地图会话缺少显式匹配。[自主桥](../scripts/go2w/plain_slam_web_bridge.py)、[手动桥](../scripts/go2w/webui_map_snapshot_writer.py)、[Web 读口](../app/manual_web_demo/slam_map_snapshot.py)、[轮询](../app/manual_web_demo/static/slam_map_3d.js)。

最短改法：两种地图桥只负责 ROS 地图、轨迹和地图健康；当前模式的语义进程从内存实体输出带地图会话标识与 frame 的对象快照，Web 组合两份已成形快照。标识不匹配时不叠画。点云按地图版本缓存，前端按实际快照周期刷新。

### P1：`/ws/search` 的跨线程队列和慢客户端

`SubprocessSearchExecutor._read_loop` 在读线程调用 service/adapter，bus 回调进入 `SearchEventHub._on_event`，对 `asyncio.Queue` 直接 `put_nowait`；该队列由 ASGI loop 中的 `_drain_loop` 消费。跨线程写 asyncio queue 不具备可靠唤醒契约，且队列无界、向客户端串行 `await send_text`。高频大图事件或慢浏览器会累积内存并拖慢其他连接。Web 的手动 `WebSocketBroadcaster` 已使用 `queue.Queue` 跨线程，说明搜索 hub 可收敛到同样的单一线程安全投递方式，再由 loop 批量广播或只保留最新状态。此项是代码路径风险，尚未通过压测量化。[搜索 hub](../app/manual_web_demo/search_routes.py)、[读线程](../app/manual_web_demo/search_executor.py)、[手动 hub](../app/manual_web_demo/web_server.py)。

### P2：路由别名和过多选型暴露

`/api/search/decisions` 与 `/history/decisions` 完全同义，后者名字还暗示持久历史，实际读的是当前内存列表。`/map`、`/place-graph`、`/frontiers`、`/semantic-map` 是同一快照的多个投影。`SearchStartRequest` 与 CLI 同时携带 `reasoner`、`backend`、`detector`、`spatial_provider`、`rtabmap`、`spatial_v2` 等选择，但生产 Web 后端固定 `nav2`，`rtabmap` 还是兼容别名；`from_dict` 中 `operator_supervised` 计算了两次。保持现有外部兼容期间，文档指定 `/api/search/state` 为网页唯一状态读口；确认外部调用方后删除同义路由和别名，生产请求只保留任务、预算、明确的安全授权和真正现场要切换的检测模式。[路由](../app/manual_web_demo/search_routes.py)、[请求](../app/manual_web_demo/search_models.py)。

## 7. 建议的最小目标结构

```text
SearchSessionService：唯一 session/命令所有者
SearchRuntime：唯一观测 -> 决策 -> Nav2 执行循环（现有 AutonomousExplorer + 接线）
SearchState：唯一当前任务/对象图/决策快照，事件只记变化
MapSnapshotWriter：唯一 ROS 地图/健康到 Web 快照转换
MotionActionServer：唯一底层运动安全终点
```

对外保持两类写入：`/api/search/start|pause|resume|stop|estop` 与 `/ws/control`；保留一个搜索状态读口 `/api/search/state`、一个事件流 `/ws/search`、一个三维地图读口 `/api/slam/map3d`、一组历史接口。内部只跨进程传**命令、事件增量和必要的传感器引用**，不在每层复制完整图。地图与对象都带坐标系和会话版本。先统一状态所有权，再删重复接口；这比把每个字段另造一个 service、adapter、provider 更直接。

配置的权威性按运行入口确定：Web 请求默认值由 `configs/go2w/autonomous_search_web.yaml`、`SearchStartRequest` 和环境变量合成；Nav2 运动授权由 `configs/go2w/navigation_gate.yaml` 与底层 gate 决定；SLAM、相机、外参由各自 ROS 启动脚本加载。`reports/`、历史计划、`outputs/`、`artifacts/` 是记录或产物，不提供运行接口。[图像入口](../run_demo.py)、[视频入口](../run_video_demo.py)、[静止观测入口](../run_live_robot_demo.py)、[旧实验壳](../scripts/go2w/start_semantic_exploration.sh)。

## 9. 可复查的验收点

1. CLI `--backend nav2` 分派回归测试通过，且不调用 `_run_offline`；本次只跑 mock/patch 测试，没有启动机器人运动。
2. 后续改图所有权时，以一次观测的图版本、Web 状态、历史恢复、三维叠画坐标版本一致为验收条件；测每次事件序列化字节数和 `webui_state.json` 重写次数，判断性能收益。
3. 后续改 WS hub 时，用读线程高频发布和慢连接测无丢唤醒、队列有界、其他客户端仍能收到最新状态。
4. 真机在线验收需另有现场监督，核对 `/map`、TF、`localization_valid`、`/go2w/motion` 唯一服务端、控制权和物理急停；本审计不以 SSH 在线等同运动授权。
