## 2. 今天完成了什么（每条都有实测证据）

### 2.1 IMU 覆盖修复 —— **本日最大成果，已正式化**

| | 修复前 | 修复后 |
|---|---|---|
| 每帧可用 IMU（`imu_n`） | 12–14（窗口覆盖 8.7%） | **24–26（100%）** |
| 去畸变残差（`dsk_max`） | 0.026–0.028 m | **0.0015–0.0023 m**（静止）/ 0.008 m（0.8 m/s） |

**根因**：LiDAR 帧窗口 0.1 s，而 IMU 比点云**晚到 ≈89 ms** ⇒ LIO 收到帧时覆盖帧末端的 IMU 还没到。
**修法**：`scripts/go2w/lidar_delay_buffer.py`（点云缓冲 0.12 s 后转发，时间戳不变）
+ `configs/go2w/plain_slam.yaml` 的 `pandar_adapted` → `/go2w/slam/pandar_points_buffered`
+ 已写进 `start_plain_slam_mapping.sh`（`GO2W_SLAM_LIDAR_DELAY_S=0` 可关，回退只需改回原话题）。
**人工确认**：用户明确表示"建的图有明显增强，差不多能用了"。

### 2.2 WebUI 三维建图修正

* WebUI 的 `/api/slam/map3d` **不订阅实时话题**，只读快照
  `outputs/autonomous_search/runtime/slam_map_3d.json`——该文件曾停留在 **8 天前**（内含 `pose=2.28e11` 坏数据），
  这是"WebUI 地图重叠"的直接来源；
* 新增 `scripts/go2w/webui_map_snapshot_writer.py`：把权威地图写成 WebUI 快照格式，
  带 range filter（1–25 m）、voxel 降采样（0.05 m）、**按地图 bounds 过滤过期坐标**；
* 已接进 `start_manual_web_demo.sh`（开关 `GO2W_WEBUI_SNAPSHOT_WRITER=0`）。

### 2.3 语义物体标注跑通 + 在 WebUI 显示

* Dataset D（原地 12×30° 转圈）：物体三维定位成功，空间质量 `METRIC_LIDAR`；
* `static/slam_map_3d.js` 新增**语义标注层**（红点 + 标签，随地图平移缩放），
  快照带 `objects` 字段；用户截图确认显示正常；

## 3. 没做什么 / 已知缺陷（诚实清单）

## 4. 被推翻的结论（**这一节请务必先读，能省下一天**）

| 曾经的结论 | 实测真相 |
|---|---|
| "WebUI 地图一直用 plain_slam，换 rko 就好" | **错**。rko 链路的 `map_3d` 是**圆形**（长方形房间被多朝向叠加），而 plain_slam 是正确长方形。**切换前必须先看地图几何**，端点位姿指标（endpoint/overlap）好 ≠ 地图正确 |
| "post-loop jitter FAIL 说明回环有问题" | 错，是**口径**把运动当抖动（已修） |
| "WebUI 地图重叠是 SLAM 后端造成的" | 部分是**旧快照**（8 天前文件），WebUI 读快照、不订阅实时话题 |
| "语义坐标可以跨会话复用" | **不能**。`pslam_map` 原点 = 会话启动时机器人位置；重启即作废（对策：重采 + bounds 过滤） |
| "WebUI 上物体标了两遍是 VLM 的问题" | **是快照读取 bug**：events.jsonl 每个物体每次更新都写一条事件，我按"事件条数"计数；下游 `object_id` 合并其实是正确的（按 `object_id` 去重即可） |
| "偏差可能是相机-激光外参问题" | **不是**。外参误差是系统性的，不会让**同一物体两次观测**互差 7–25 cm（偏移离散度 std 0.212 ≈ 均值 0.208 m） |

## 6. 接下来做什么（按性价比排序，均可离线验证）

1. **实例关联重做（收益最大）**：现在"同一标签只保留一个实例"，导致 D1（漏检）+ 可能的误合并。
   建议改为：**同一标签按空间聚类→多个实例**，再用 `object_id`/多帧计数做去重；
   多观测融合从"取合并值"改为**中位数**。
2. **大物体中心定义**（治 D3）：桌子一类改用"最近稳定表面"或"正前方对齐点"，而非检测框中心。
3. **深度采样优化**（治 D2 中的细长物体）：见 `docs/SLAM_VALIDATION_REPORT.md` §3.5.10 三条候选
   （候选簇中取最远者 / 贴地先验 / 用 bbox 下半部采样）——**每改一条都要同场景重采验证**，避免引入反向偏差。
4. **重做定点观测实验**（治 D8）：外网稳定后跑 `/tmp/run_semantic_static.sh`，分离深度误差与视角差异。
5. **提高检测密度**（治 D1）：VLM 单次延迟 26 s 是密度瓶颈；可评估更快的模型或降分辨率。
6. **rko 路线（可选）**：若要继续换后端，先做**契约验证**——逐帧比对桥接发出的 pose/scan
   与 plain_slam 的差异，重点查"点云坐标系与位姿语义是否错了一层"（圆形地图的嫌疑）。

## 7. 坑与注意事项

1. **禁止** `git add .` / `reset` / `clean` / `checkout`：仓库有 ~211 项未提交改动，分支
   `fix/go2w-autonomous-search-lio-topology-target`；
2. **`kill` launch 的子进程会让整个 plain_slam 栈退出**（今日实际踩到，用 `start_plain_slam_mapping.sh` 恢复）；
   要停映射栈请用 `stop_plain_slam_mapping.sh`；
3. **重启映射栈 = 作废语义坐标**（D4）：先采语义后别重启；或重启后重采；
4. **轮式 odom 只做运动学参考**，不用于"是否回到原点"判定（D6）；
5. **WebUI 的 frame 契约**：`slam_web_map_state` 只接受 `pslam_map`，否则 `map_frame_mismatch` 拒收；
6. **QoS 陷阱**：桥接/relay 混用 RELIABLE 与 BEST_EFFORT 会静默收不到数据
   （WebUI 的 web_scan、bag 录制都踩过）；
7. **外网不稳定**（D7）：涉及 VLM 的流程要有重试与降级，不要把它当稳定依赖；
8. **地图几何必须先目视再判定**：`scripts/go2w/map_watch.py` 会每 30 s 输出
   `aspect`（长宽比）与 `fill`（填充率）——长方形房间约 `aspect>2 / fill≈0.22`，
   一旦 `aspect` 掉到 ~1.1、`fill` 涨到 0.4 就是"被叠成圆"（rko 的典型症状）。
