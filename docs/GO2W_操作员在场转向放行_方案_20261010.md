# 操作员在场时的转向放行 —— 方案（待审批）

日期：2026-10-10　　状态：**已批准、已落地、已真机验证（见文末）**　　关联：整改复核记录 §5.5 待审批表 D 项

## 一句话

桥（`go2w_cmd_vel_bridge`）现在把**任何带转向的命令整条清零**，因为 `rotation_clearance_valid`
是 `false`。本方案给它加一条**显式、单独、默认关**的启动开关：操作员声明"我在现场"时，
桥允许转向，但**只豁免这一条**，其余所有闸门照拦，且每次放行都在状态串里写明是靠操作员监督放行的。

## 为什么要走这条路（现场事实）

1. 桥读的是话题 `/go2w/safety/rotation_clearance_valid`（`bridge_node.py:63`），
   由雷达预处理器按 `lidar_preprocess.yaml` 的**持久**声明发布。
2. 持久声明要 `valid:true` + 五项 checks 全真 + 证据路径 + 硬件哈希绑定。其中
   `near_field_blind_zone_mitigated` 对应的物理事实是**雷达看不见自身近场**：
   `GO2W_REAL_ROBOT_DEPLOYMENT.md` 实测 **720/720** 个采样方位不可观测，
   最差径向空隙 **~0.291 m**。
3. 现成的测量工具 `validate_rotation_clearance_physical_ros.py` 产出的是 **pose-bound**
   证据（`initial_pose_in_place_rotation_only`，≤0.03 m / ≤900 s），
   `config.py:217-220` **明确拒收**它去开持久门；且自主搜索（`run_semantic_exploration.py`）
   把 `_rotation_lease_path` 写成硬编码空串，**不读任何租约**。
4. 结论：**持久门在软件上开不了**，要开只能补盲传感器 / 重验雷达安装（硬件）。
   本方案走的是第三条路：**不改净空判定，而是给"人在现场"这个已授权场景一条正规通道**。

## 设计（最小改动）

### 1. `bridge_core.py` —— 加一个字段，改一个条件

```python
@dataclass(frozen=True)
class SafetyState:
    ...
    rotation_clearance_valid: bool = False
    operator_supervised_rotation: bool = False   # 新增；fail-closed 默认
```

```python
if (
    abs(requested.angular_z) > 1e-9
    and not safety.rotation_clearance_valid
    and not safety.operator_supervised_rotation      # 唯一的放宽点
):
    blockers.append("rotation_clearance_unvalidated")
```

- 豁免**只**作用于这一条。`emergency_stop` / `remote_override` / `operator_not_armed` /
  `lease_alive` / `lidar_fresh` / `robot_error_zero` / 定位新鲜 / 看门狗 —— **全部照旧**。
- 默认 `False` ⇒ 不传这个开关时，`bridge_core` 的行为**逐位等同于现在**。

### 2. `bridge_node.py` —— 从**启动参数**读，不从话题读

```python
self.declare_parameter("operator_supervised_rotation", False)
```

传进 `SafetyState`（`bridge_node.py:98` 那处构造）。

**为什么是参数而不是话题（这是本方案的核心安全属性）**：
话题**任何进程都能发**；参数**只有启动这个栈的那条命令能给**。走参数，
"这条豁免只能由启动栈的人开启"就是**结构性**的，不靠约定。
这也与本仓既有先例一致：`nav2_allow_execute` 是用户手改的 YAML，
搜索侧 `--operator-supervised-experiment` 是命令行开关 —— 都是"操作员断言"，不是"传感器读数"。

### 3. 状态串必须写明放行理由

`/go2w/cmd_vel_bridge/status`（`bridge_node.py:113`）现在只发 `selected` / 阻塞原因。
放行时改成能区分来源的值，让每一条靠豁免放行的命令在话题上**看得出是豁免**，
而不是看起来像"净空已验证"。

> 这条不是装饰：**假绿**是本项目反复吃过的亏。若豁免后的状态与"净空通过"不可区分，
> 事后就无法从话题上判断哪一次转向是有物理依据的。

### 4. 启动脚本 —— 一个显式开关

`start_nav2_autonomous_search.sh:208` 现在是：

```bash
setsid bash -c 'exec ros2 run go2w_cmd_vel_bridge bridge --ros-args -p execution_enabled:=true' ...
```

加一个**独立**开关（建议长名、无短别名），只在显式传时追加
`-p operator_supervised_rotation:=true`，并在启动横幅里打印它当前是开是关。

**不复用 `--enable-motion`**：那个开关已经管着 `nav2_allow_execute`。
安全豁免应当是一次一个、各自可审计的。

### 5. `run_autonomous_loop.py:800` 的进程内闸门

保持默认 `False`，**不动**（`cmd_vel_gate` 本身默认 `off`，不在活路上）。

## 判据（写完必须全过）

| # | 断言 | 类型 |
| --- | --- | --- |
| 1 | 默认 `False` + 带转向命令 ⇒ 仍然 `rotation_clearance_unvalidated` | 回归护栏（钉住现状） |
| 2 | `True` + 带转向命令 ⇒ 放行 | 新能力 |
| 3 | `True` + 急停拉高 ⇒ **仍然**拦 | 豁免不外溢 |
| 4 | `True` + `remote_override=True` ⇒ **仍然**拦 | 豁免不外溢 |

**反向校准**（每次都要做）：把豁免写死 `True` ⇒ **只有**断言 1 失败；
写死 `False` ⇒ **只有**断言 2 失败。各自只打中对应断言才算这组测试有分辨力。

**参数表对不上就是旧码在跑**（本项目栽过这个坑）。

## 明确不做

- **不**伪造 `/go2w/safety/rotation_clearance_valid`（不建恒真发布者）。
- **不**改 `lidar_preprocess.yaml`、不碰持久门、不碰任何证据文件。
- **不**动急停锁存（B 项）。
- **不**动 `remote_override` 的默认拦（C 项，独立决策）。
- **不**动 Nav2、**不**动搜索侧已有的 `--operator-supervised-experiment`。
- **不**在桥这一层新增转向幅度限制（见下方边界说明）。

## 风险与边界（如实写）

1. **这条通道的安全性完全依赖现场那个人。** 近场盲区是**真实存在**的
   （最差 0.291 m 不可观测）。豁免之所以可以接受，前提是"人在现场手持即停"，
   而不是"净空已被证明"。这一点必须写在文档和启动横幅里，不能含糊。
2. **桥是速度级，没有"每步 ≤30°"这种约束能力。** 搜索侧已有的
   `--operator-supervised-experiment` 管的是每步 ≤30°；桥这一层管的是速度上限
   （`maximum_angular_z = 0.20 rad/s`，不变）。
   若你要求桥这一层也收窄（例如监督模式下把角速度上限降到更低），
   那是**新增设计**，默认不做，等你单独指示。
3. **豁免不解除别的门。** 所以它不会让"没武装 / 没租约 / 急停中"的狗动起来。

### 真机"转一次" —— 已完成（2026-10-10）

前置（用户批准 C 之后）：代理以 `--remote-override-cleared=true` 重启 ⇒
`/go2w/remote_override=false`（pubs=1）；桥以
`-p execution_enabled:=true -p operator_supervised_rotation:=true` 重启 ⇒
`ros2 param get … operator_supervised_rotation` = `True`（pubs=1）。

动作形式（最小可判读）：**原地纯转向** —— `/go2w/manual_cmd_vel` 上
`Twist(linear.x=0, angular.z=0.15)`，20 Hz × 40 帧 = 2.0 s。
角速度取 0.15（上限 0.20，留余量）；`linear_x` **全程 0**，只转不走。

| 判据 | 实测 |
| --- | --- |
| 狗真的转了 | wheel odom yaw **−84.24° → −79.59°**，即 **+4.65°** |
| 两路里程计一致（排除轮子空转假象） | fused −84.33° → −79.59°，与 wheel 同向同量 |
| 停得干净 | 静置 3 s 连读三次：−79.58 / −79.57 / −79.62°，±0.05° 属噪声 |
| **状态串写明是靠豁免** | `/go2w/cmd_vel_bridge/status` 出现 **45 个连续帧** `allowed_operator_supervised_rotation`；窗口前后均为 `allowed`，整段录制**只有这两种取值** |
| 仲裁器确实选中了它 | `/go2w/control_status` 出现 `selected`（另有 `all_command_sources_stale` 的空闲帧） |
| **只有净空这一条被豁免** | 同一时刻其余门是**真的**绿：`lidar_fresh=true`、`robot_error_zero=true`、`sport_lease/alive=true`、`localization_valid=true`；唯独 `rotation_clearance_valid=false` 被豁免绕过 |

**一个非显然的量化事实（记下来，别再按"速度×时间"估）**：请求 2.0 s × 0.15 rad/s
本应约 0.272 rad ≈ 15.6°，实际只有 **4.65°（0.081 rad）**，约为朴素估算的 **1/3.4**。
成因是链路延迟 + 加速度整形 + 网关限幅的叠加，**本轮没有去分解这三者**，
所以别引用任何单一成因，只记住"朴素估算会高估三倍上下"。
