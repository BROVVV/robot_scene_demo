# Go2-W 机器狗失联交接（2026-09-15 17:25）

## 结论

**17:25:23 起机器狗网段链路物理中断，狗不可达。** 按 §10.4 常设规则处理：
失联即假设没电，停止工作，写本文件。

**证据边界（必须如实转述）**：`carrier=0` 只能证明链路断了，无法区分
"狗没电了" 和 "有人拔了网线"。下文按规则采用"假设没电"，但那是 §10.4 的
约定，不是已确立的事实。恢复时的第一步是接回网线并确认狗是否上电。

## 恢复步骤

1. 接回 `enp3s0`，确认本机重新拿到 `192.168.123.99`，`ping 192.168.123.18` 通。
2. **若狗确实没电**：充电后重启狗。注意重启后运动栈的 SDK 链接会死
   （进程活着、pub=1、fused odom 照跑，全是假绿）——判据是 `/tmp` 状态文件
   mtime 是否推进，不是进程存活。
3. 重启 plain_slam 栈，**重跑前置检查**（失联/重启不继承上一批的运动授权前提）。
4. ⚠ **WebUI 进程载入的仍是旧模块**：`app/manual_web_demo/search_executor.py` 的
   `PYTHONNOUSERSITE` 修复需**重启 WebUI 才生效**。重启前从 WebUI 点「开始搜索」
   仍会 0.5 秒 FAILED。前端静态文件刷新即生效。
