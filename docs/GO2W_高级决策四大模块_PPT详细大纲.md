# GO2W 高级决策四大模块 PPT 精简大纲

> 共 5 张内容页，不包含封面、目录和项目概述。  
> 汇报主线：任务 Agent 组织任务，多模态视觉形成证据，三维地图与拓扑图融合为空间认知，WebUI 展示决策依据。

---

## 第 1 页｜任务 Agent：从指令理解到总体任务管理

### 页面核心结论

新版本以任务 Agent 统一管理“理解目标—制定计划—选择方向—执行检查—根据结果重规划”的完整过程，使每一步搜索都有明确目标、上下文和退出条件。

### 建议放在 PPT 上的内容

- **任务结构化**
  - 将自然语言任务转换为目标类别、属性、空间关系和约束条件。
  - 通过 GoalGraph 表达“先找什么、依赖什么、满足什么条件才能进入下一阶段”。
- **分层任务规划**
  - 总体计划：搜索目标、优先区域、验证条件、终止条件。
  - 当前子任务：观察、探索、接近、验证或重新规划。
  - 原子动作：转向候选方向、移动至前沿、前往目标视点。
- **全量上下文决策**
  - 决策输入同时包含知识库、场景图、拓扑图、三维物体、历史观测、负证据、方向覆盖率、当前航向和安全约束。
  - Agent 不直接发运动指令，只输出结构化搜索意图和候选方向优先级。
- **动态任务管理**
  - 发现新证据时提升相关区域优先级。
  - 连续未发现目标时写入负记忆，并切换到信息增益更高的未探索区域。
  - 目标证据不足时进入验证阶段，而不是立即宣布找到。

### 算法设计

候选动作采用“硬约束过滤 + 词典序排序”，避免单一加权分数掩盖安全问题：

\[
a^*=\arg\max_{a\in A_{safe}}
\left(
G_{task}(a),
G_{evidence}(a),
G_{topology}(a),
G_{coverage}(a),
-C_{repeat}(a)
\right)
\]

- \(A_{safe}\)：满足可通行性、最小净空和执行条件的候选集合。
- \(G_{task}\)：与当前子任务的匹配程度。
- \(G_{evidence}\)：目标、属性和关系证据强度。
- \(G_{topology}\)：候选方向与位置图、前沿节点的连通价值。
- \(G_{coverage}\)：预计新增可观测空间。
- \(C_{repeat}\)：重复旋转、重复访问和负记忆惩罚。

当存在有效导航锚点时优先生成“面向空间目标”的动作；没有有效锚点时，才使用未观测扇区和 Frontier 进行探索，从机制上让自主搜索更倾向于扩大有效覆盖。

### 推荐图示

绘制一条横向闭环：

~~~text
任务解析 → GoalGraph → 总体计划 → 当前子任务 → 候选动作排序
   ↑                                             ↓
   └──── 新证据 / 负证据 / 执行结果 ← 状态检查 ────┘
~~~

右下角增加一个候选动作小表格：方向、任务收益、证据收益、拓扑收益、覆盖收益、重复惩罚、最终选择。

### 汇报时重点讲

这套 Agent 的核心不是增加一段自然语言推理，而是建立可执行、可检查、可重规划的任务状态机；复杂任务被拆成有依赖关系的阶段，每一步都有明确输入、选择依据和完成条件。

## 第 2 页｜多模态视觉感知：从开放词汇发现到可信目标证据

### 页面核心结论

新版本建立“类别发现—文本定位—像素分割—语义复核—证据融合”的多模态感知链，将不同模型的专长组合成可供高级决策直接使用的结构化证据。

### 建议放在 PPT 上的内容

- **目标语义标准化**
  - TargetProfile 保存目标类别、同义词、外观属性、参考物关系和验证条件。
  - 用户表达先映射到统一目标词表，减少同一物体多种叫法造成的检索遗漏。
- **开放词汇候选发现**
  - RAM++ 提取图像级语义标签，用于发现画面可能包含的对象。
  - GroundingDINO 根据目标文本生成候选框及置信度，实现开放词汇定位。
- **精细区域提取**
  - SAM2 根据候选框生成像素级掩码，为深度投影、尺寸估计和三维定位提供准确区域。
- **多模态语义复核**
  - 对低置信度、属性相似或关系复杂的候选，使用视觉语言模型检查类别、属性和上下文是否满足任务。
  - 付费 API 不是离线流程的必需条件；离线回放可使用已录制模型结果和缓存证据。
- **三态目标证据**
  - **PRESENT**：类别、置信度、空间质量和必要属性满足确认条件。
  - **POSSIBLE**：存在相关候选，但仍需换视角或补充验证。
  - **ABSENT**：只有在当前视角的模型链实际运行且具备分辨能力时才成立。

### 算法设计

将检测置信度、分割质量、深度质量、语义一致性和关系一致性融合为证据分数：

\[
C_{target}=
w_dC_{det}+w_mQ_{mask}+w_zQ_{depth}
+w_sC_{semantic}+w_rC_{relation}
\]

最终状态并非简单按“有框/没框”判断，而是结合感知能力与阈值：

~~~text
高质量且满足验证条件         → PRESENT
有相关信号但信息不充分       → POSSIBLE
判据有效且确认未检出         → ABSENT
模型未运行、数据过期或不可判 → UNKNOWN/不写入负证据
~~~

所有证据携带时间戳、来源模型、帧号、目标词、阈值和空间质量，使任务 Agent 能区分新鲜证据、过期证据和不可判定结果。

### 推荐图示

~~~text
RGB 图像
  ├─ RAM++：场景标签
  ├─ GroundingDINO：文本候选框
  └─ SAM2：目标掩码
           ↓
     RGB-D 空间定位
           ↓
   VLM 属性/关系复核
           ↓
PRESENT / POSSIBLE / ABSENT
~~~

旁边放一张目标图像，叠加候选框、分割掩码、置信度和证据状态。

### 汇报时重点讲

算法的优势是把“看见什么”和“能否据此决策”分开：模型输出必须经过质量评估、语义复核和证据状态转换，只有具备分辨力的观测才能影响任务完成判断或形成负记忆。

## 第 3 页｜三维地图与拓扑图融合：构建统一语义导航图

### 页面核心结论

新版本以机器人位姿和 Place 节点为连接桥梁，将三维地图的几何位置、可通行区域和探索边界，与拓扑图的地点连接、物体语义和访问记忆，融合为统一的 SemanticNavigationGraph。

任务 Agent 因此可以同时回答：

- 空间上能不能到达？
- 应该优先前往哪个地点？
- 目标可能位于哪些物体或区域附近？
- 哪条路线的信息增益更高、代价更低？

### 建议放在 PPT 上的内容

- **统一坐标**
  - 建立 camera → base_link → map/odom 的坐标链。
  - 位姿与物体保留坐标系、变换来源和空间质量等级。
  - 坐标系不一致时拒绝直接融合，避免错误的米制距离和位置关系。
- **Place 空间锚定**
  - 将连续三维轨迹聚合为稳定的 Place 节点。
  - 原地转动只更新当前 Place 的航向覆盖，不重复创建地点。
  - 发生有效平移时创建新 Place，回到已有区域时复用旧 Place 形成闭环。
- **语义实体挂载**
  - 持久 Object 通过 OBSERVED_FROM 连接到观测它的 Place。
  - Place 之间使用 CONNECTED_TO 表示移动连接。
  - 未探索边界通过 FRONTIER_TO 挂载到对应 Place。
  - 物体之间保留 NEAR、LEFT_OF、IN_FRONT_OF 等空间关系。
- **双层联合规划**
  - 拓扑图负责选择目标区域和规划全局地点序列。
  - 三维地图提供 Frontier 坐标、距离、信息增益和局部净空。
  - 执行成功、失败和阻塞状态回写拓扑边，持续修正后续路径。

### 融合结构

~~~text
┌───────── 三维几何层 ─────────┐       ┌───────── 拓扑语义层 ────────┐
│ 点云 / 占据地图 / 机器人位姿 │       │ Place / 连通边 / 访问记忆   │
│ Free / Occupied / Unknown    │       │ 物体语义 / 负证据 / 失败历史│
│ Frontier / 距离 / 局部净空   │       │ 方向覆盖 / 目标相关性       │
└────────────┬─────────────────┘       └───────────┬────────────────┘
             │       坐标对齐 + Place 锚定         │
             └────────────────┬────────────────────┘
                              ▼
               ┌── SemanticNavigationGraph ──┐
               │ PLACE ─ CONNECTED_TO ─ PLACE│
               │   │                    │     │
               │ OBSERVED_FROM       FRONTIER_TO
               │   │                    │     │
               │ OBJECT ─ relation ─ OBJECT  FRONTIER
               └──────────────┬───────────────┘
                              ▼
                  候选排序 → 全局选路 → 局部校验
~~~

### 算法设计一：Place 关联

将当前位姿 \(\mathbf p_t\) 与已有 Place 中心 \(\boldsymbol\mu_i\) 做最近邻关联：

\[
i^*=\arg\min_i\|\mathbf p_t-\boldsymbol\mu_i\|_2
\]

~~~text
平移量 < 0.10 m
    → 保留当前 Place，只更新观测方向与语义

发生有效平移，且最近 Place 距离 ≤ 0.60 m
    → 复用已有 Place，形成重访或闭环

发生有效平移，且没有邻近 Place
    → 创建新 Place，并增加 CONNECTED_TO 边
~~~

Place 因而成为两类地图的公共索引：它既保存真实空间位姿，也关联观察方向、语义物体、负证据与访问历史。

### 算法设计二：几何与语义联合评分

任务 Agent 对候选 Frontier 或目标区域计算：

\[
S(f)=
w_sS_{semantic}
+w_iG_{information}
+w_nS_{novelty}
+w_mS_{memory}
-w_rC_{route}
-w_vP_{visited}
-w_fP_{failure}
-w_eP_{negative}
\]

- \(S_{semantic}\)：候选区域与搜索目标的语义相关性。
- \(G_{information}\)：三维地图估计的空间信息增益。
- \(S_{novelty}\)：区域未探索程度。
- \(S_{memory}\)：知识库和历史观测提供的先验。
- \(C_{route}\)：拓扑路径长度或米制距离代价。
- \(P_{visited}\)、\(P_{failure}\)、\(P_{negative}\)：重复访问、通行失败和有效负证据惩罚。

拓扑路径使用 Dijkstra 求解，BLOCKED 边不参与当前搜索；边的距离、失败次数和退化状态共同构成路线代价。选出全局地点序列后，再由三维地图检查局部坐标、净空与可达性。

### 推荐图示

页面采用“三列融合图”：

- 左侧放三维点云或占据地图，标出机器人、障碍物、未知区和 Frontier。
- 中间放统一语义导航图，使用蓝色 Place、绿色 Object、橙色 Frontier。
- 右侧放联合决策结果，高亮目标 Place、拓扑路线和局部三维目标。
- 同一实体在三张图中保持相同颜色，直观展示“三维位置 → 拓扑节点 → 决策目标”的映射。

### 汇报时重点讲

融合层让三维地图和拓扑图通过 Place 共享同一空间索引。高级决策先用拓扑语义回答“去哪个区域、经过哪些地点”，再用三维几何回答“目标坐标在哪里、局部是否可通行”。最终得到的是同时具有空间依据、语义依据和路线依据的下一步决策。

## 第 4 页｜决策过程可视化：让每一步选择都可查看、可解释、可复现

### 页面核心结论

新版本通过 DecisionTrace 将任务计划、上下文证据、候选动作、评分结果和最终选择同步到 WebUI，形成结构化决策审计，而不是展示不可验证的长篇“思维过程”。

### 建议放在 PPT 上的内容

- **总体任务面板**
  - 显示总体目标、阶段计划、当前子任务、完成条件和下一检查点。
  - 用时间轴展示“搜索—发现候选—换视角验证—确认目标”等状态变化。
- **决策上下文面板**
  - 展示本轮读取的知识库条目、SceneGraph、PlaceGraph、目标证据、负记忆和方向覆盖率。
  - 每条信息标注来源、时间戳、新鲜度和可信度。
- **候选动作面板**
  - 同时展示前进、左转、右转、前往 Frontier、靠近候选目标等动作。
  - 对每个候选显示任务收益、证据收益、信息增益、可达性、安全性和重复惩罚。
  - 明确标识被硬约束淘汰的原因以及最终入选动作。
- **决策结果面板**
  - 显示“选择了什么”“依据哪些证据”“哪些不确定性仍存在”“下一步期待获得什么新信息”。
  - 将推理建议、导航候选和最终决定通过统一 ID 关联，支持从 UI 追溯到原始帧和地图实体。
- **离线回放**
  - 使用真机录制的 RGB-D、位姿、检测与拓扑数据重放每个决策周期。
  - 支持逐帧暂停，核对当时可用信息、候选排名和决策输出，不连接机器狗、不发送运动指令。

做一张 WebUI 线框图：

### 汇报时重点讲

可视化展示的是影响决策的结构化事实和评分，不暴露冗长内部推理文本。这样既便于理解机器人为何选择某个方向，也便于定位感知、建图、知识检索或规划中的具体问题。

## 第 5 页｜高级决策闭环：感知、认知、规划与验证协同运行

### 页面核心结论

四个模块通过统一数据协议形成闭环：多模态视觉产生带质量的证据，三维地图与拓扑图融合层将证据挂载到统一空间图，任务 Agent 基于任务与地图选择最有价值的下一步，DecisionTrace 将全过程送入 WebUI 和离线评估系统。

### 建议放在 PPT 上的完整流程

~~~text
用户任务
   ↓
Task Agent：目标解析、GoalGraph、阶段规划
   ↓
上下文装配：知识库 + SceneGraph + PlaceGraph + 历史记忆
   ↓
候选生成：目标视点 + 可达位置 + Frontier + 未观测扇区
   ↓
安全门控与多维排序
   ↓
离线动作意图（仅记录，不发送控制指令）
   ↓
真机录制数据中的下一帧观测
   ↓
RAM++ / GroundingDINO / SAM2 / VLM
   ↓
PRESENT / POSSIBLE / ABSENT 证据
   ↓
三维地图、PlaceGraph、语义实体和负记忆融合更新
   └──────────────────────→ Task Agent 重规划

全流程同步生成 DecisionTrace → WebUI
~~~

### 三个关键闭环

1. **任务闭环**
   - 总体目标被拆解为阶段和子任务。
   - 每个子任务具备进入条件、完成条件、失败条件和重规划条件。

2. **证据闭环**
   - 搜索动作的目的不是单纯改变朝向，而是获取能减少不确定性的观测。
   - 新观测经过检测、分割、空间定位和关系验证后更新证据状态。
   - 只有具备分辨力的观测才能形成“未发现目标”的负证据。

3. **空间闭环**
   - 当前视角通过 Place 锚点同步更新三维地图、语义实体和 PlaceGraph。
   - 覆盖率、Frontier、已访问位置与负记忆共同影响下一轮候选排序。
   - 当局部信息不足时，决策自然转向高信息增益的可达区域。

### 建议展示的离线案例

使用一段真机录制数据展示 4 个连续决策周期：

| 周期 | 当前阶段 | 关键证据 | Agent 决策 | 世界模型变化 |
|---|---|---|---|---|
| 1 | 区域探索 | 目标未知，右侧存在高价值 Frontier | 前往右侧前沿 | 新增 Place 与覆盖扇区 |
| 2 | 候选发现 | 检测到低置信度目标 | 进入 POSSIBLE，规划补充视角 | 新增暂定 Object |
| 3 | 主动验证 | 分割和深度质量不足 | 调整观察角度 | Object 获得新观测 |
| 4 | 目标确认 | 类别、属性、空间关系一致 | 标记 PRESENT，完成搜索阶段 | Object 与 Relation 转为 confirmed |

### 算法优越性落点

- **全局性**：每个动作服务于总体任务和当前阶段，而不是孤立地产生方向。
- **证据性**：结论由可追溯的视觉、空间、知识和历史证据共同支持。
- **空间性**：决策直接面向三维实体、拓扑位置和探索前沿。
- **主动性**：信息不足时主动选择能够提升可观测性和信息增益的视点。
- **可审计性**：每一轮输入、候选、淘汰原因、最终选择和结果均可离线复现。
- **安全性**：离线评估仅输出动作意图，不连接真机、不发送任何运动命令。

### 推荐图示

最终成果是一套完整的高级决策闭环：机器人能够理解任务、维护空间认知、主动选择信息价值更高的观察位置、依据多模态证据更新判断，并把每一步决策完整呈现在 WebUI 中。

---

## 制作建议

- 每页只保留一个醒目的结论句，详细算法用于讲解或动画逐步出现。
- 第 1、3、5 页以流程图和语义图为主；第 2 页以真实视觉结果为主；第 4 页以 WebUI 原型为主。
- 公式每页不超过两个，变量解释紧贴公式放置。
- 汇报时间建议为 8～10 分钟，每页约 1.5～2 分钟。
- 演示时明确说明：系统基于录制数据离线运行，仅生成和记录决策意图，不下发运动控制。
