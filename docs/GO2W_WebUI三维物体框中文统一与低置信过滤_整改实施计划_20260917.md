# GO2W WebUI 三维物体框中文统一与低置信过滤整改实施计划

> 编制日期：2026-09-17  
> 适用仓库：`/home/mxt/robotscene`  
> 目标读者：后续直接实施修改的 AI / 开发者  
> 本文性质：基于当前代码与最新一轮真机自主搜索数据的实施任务书；本文不直接修改业务代码。

## 1. 目标与最终效果

本次整改只解决以下两件事，同时不得破坏目标搜索、原始取证和三维定位链路：

1. WebUI 三维地图中所有物体框只显示中文名称，不再混出 `bin`、`barrel`、`speaker` 等英文。
2. 低置信、未稳定确认、明显不是独立物体的框不进入持久语义地图和 WebUI 三维标注层。

整改后的核心原则：

- 英文原始类别继续保留为机器内部字段，用于 GroundingDINO 提示词、问题追踪和实体关联。
- 中文显示名使用独立字段 `label_zh`，WebUI 不再直接渲染原始 `label`。
- 原始逐帧检测仍写入 `semantic_frame_objects_localized`，不能因显示过滤而丢失取证数据。
- 持久语义地图入口与 WebUI 显示层各有一道门，不能只在浏览器里把噪声“藏起来”。
- 目标框只有经过明确视觉复核后才允许绕过普通显示门限；普通 GroundingDINO 候选不能因“可能是目标”而自动放行。

## 2. 本轮排查结论

### 2.1 实际数据证据

最新一轮真机会话为：

```text
outputs/live_runs/search_20260917_190603_df66d115/events.jsonl
```

该会话共产生 41 个不同的持久物体 ID：

- 30 个最终置信度低于 `0.35`；
- 现有快照写入器以固定门限 `0.35` 过滤后，仍有 11 个物体上屏；
- 这 11 个中有 7 个仍是 `TENTATIVE`，只有 4 个是 `CONFIRMED`；
- 当前三维快照确实混合显示了：

```text
办公椅、bin、barrel、地面、purple、黑色底座、stool、lid、hook、curtain、speaker
```

其中典型数据如下：

| 原始名称 | 置信度 | 观测次数 | 状态 | 当前是否上屏 |
|---|---:|---:|---|---|
| 办公椅 | 0.822 | 1 | TENTATIVE | 是 |
| purple | 0.754 | 3 | CONFIRMED | 是 |
| bin | 0.694 | 1 | TENTATIVE | 是 |
| barrel | 0.673 | 1 | TENTATIVE | 是 |
| stool | 0.565 | 1 | TENTATIVE | 是 |
| 黑色底座 | 0.530 | 3 | CONFIRMED | 是 |
| curtain | 0.511 | 1 | TENTATIVE | 是 |
| 地面 | 0.457 | 3 | CONFIRMED | 是 |
| speaker | 0.395 | 5 | CONFIRMED | 是 |

这说明“已经有 `0.35` 门限”并不等于问题已经解决：现有策略只看单个分数，不看实体确认状态，也没有排除颜色、地面、角落等非独立物体标签。

### 2.2 中文和英文混用的完整原因链

当前真实链路如下：

```text
RAM++ 输出英文开放词表
  -> filter_ram_scene_terms() 只过滤少量词
  -> GroundingDINO 用英文 term 检测，并把该 term 当 label
  -> vocabulary.label_zh() 只查有限 TERM_ZH
  -> 词典未命中时原样返回英文
  -> LiveSemanticObserver / DepthObjectLocalizer / SemanticObjectMap
  -> semantic_object_localized 事件
  -> webui_map_snapshot_writer.py 读取 object.label
  -> slam_map_3d.js 原样绘制 item.label
```

关键代码事实：

1. `app/detectors/grounded_sam_worker.py::_predict_all_prompts()` 有意把英文 prompt term 直接作为检测标签。
2. `app/detectors/vocabulary.py::label_zh()` 在 `TERM_ZH` 未命中时返回原始字符串；因此开放词表中的 `bin/barrel/stool/lid/hook/curtain/speaker` 会保持英文。
3. RAM++ worker 实际同时返回 `tags_en` 和 `tags_zh`，但 `GroundedSAMSubprocessDetector.discover_scene_terms()` 只消费 `tags_en`，中文标签被丢弃。
4. `scripts/go2w/run_autonomous_loop.py::_gsam_to_dict()` 没有完整透传 `category`、`source_prompt_term` 等语义字段。
5. `scripts/go2w/run_semantic_exploration.py::analyze_semantic()` 又把类别统一覆盖为 `object`，使后续无法可靠区分“地面/属性词/真正物体”。
6. `scripts/go2w/webui_map_snapshot_writer.py::_load_objects()` 只输出 `obj.label`；`app/manual_web_demo/static/slam_map_3d.js` 也只渲染 `item.label`，两端都没有中文显示契约。

因此，本问题不能只靠前端加一个小词典解决。前端翻译只能覆盖已知词，下一次 RAM++ 出现新开放词时还会重新漏出英文。

### 2.3 低置信框进入地图的原因链

当前检测默认参数为：

```text
GROUNDING_DINO_BOX_THRESHOLD=0.12
GROUNDING_DINO_TEXT_THRESHOLD=0.10
GROUNDING_DINO_HIGH_RECALL_BOX_THRESHOLD=0.10
SAM2_MIN_BOX_SCORE=0.35
MAX_DETECTED_OBJECTS=100
```

这些参数本来就是偏召回配置。其合理用途是“先多找候选，再由后级筛选”，但当前后级存在断层：

1. `grounded_sam_worker.py` 对低于 `SAM2_MIN_BOX_SCORE=0.35` 的框只是不跑 SAM2，并没有丢弃检测框。
2. `run_semantic_exploration.py` 随后仍会定位并把这些低分对象送入 `SemanticObjectMap`。
3. `SemanticObjectMap.update_with_associations()` 创建实体时没有最低观测置信度门限。
4. `SemanticObjectMap._merge()` 使用 `max(entry.confidence, obs.confidence)`；一次偶然高分会永久成为实体置信度，之后低分重复观测不会把它拉低。
5. 实体 `CONFIRMED` 主要由观测次数决定，没有同时要求置信度合格。
6. WebUI 写入器只有固定的 `MIN_OBJECT_CONFIDENCE = 0.35`，也不检查 `status`、`observation_count`、类别和中文字段。

这会造成两种污染：

- 低于 `0.35` 的对象虽然暂时不上 WebUI，但已经进入持久实体图并参与后续关联；
- 高于 `0.35`、但只出现一次或本身不是物体的标签仍直接上屏。

## 3. 必须保持的边界

实施 AI 必须遵守以下约束：

- 不提高 GroundingDINO 的底层召回门限来代替后级过滤。目标搜索仍需要高召回候选。
- 不删除或改写已有 `events.jsonl`；历史数据只读。
- 不把中文显示名称反向用于 GroundingDINO prompt。
- 不在浏览器调用在线翻译服务；显示名称必须可复现、可离线测试。
- 不把不同未知类别全部用同一个中文词作为实体关联键，否则会增加错误合并。
- 不破坏 `frame_object_id -> persistent_object_id` 的严格关联，不得改回按 label 或列表下标猜测。
- 当前工作区已有大量未提交修改，实施时不得执行 `git reset --hard`、`git checkout --` 或覆盖无关改动。

## 4. 统一数据契约

### 4.1 标签字段

从检测结果开始，统一保留以下字段：

```json
{
  "label": "speaker",
  "label_zh": "音箱",
  "category": "electronics",
  "source_prompt_term": "speaker"
}
```

字段语义：

- `label`：规范化后的原始/英文类别，供检测、实体关联和调试使用，不直接展示。
- `label_zh`：稳定中文显示名，供 WebUI 和中文报告使用。
- `category`：物体类别，用于排除颜色、背景、画面区域等非独立对象。
- `source_prompt_term`：GroundingDINO 实际使用的 term，供审计。

历史事件缺少 `label_zh` 时，快照写入器允许调用同一个离线解析函数补齐，但不能把英文直接回退给前端。

### 4.2 置信度字段

持久实体建议至少保留：

```json
{
  "confidence": 0.58,
  "confidence_max": 0.82,
  "confidence_observation_count": 3,
  "observation_count": 3,
  "status": "CONFIRMED"
}
```

- `confidence`：用于显示判定的聚合置信度，建议采用累计平均或有界 EMA，不能继续只存最大值。
- `confidence_max`：仅用于审计，记录历史最高分。
- `confidence_observation_count`：参与聚合的有效观测数。
- 兼容历史数据：缺少新字段时将旧 `confidence` 视为一次观测，但必须继续结合 `status/observation_count` 过滤。

## 5. 推荐门限与判定规则

### 5.1 持久语义地图入口门

推荐新增配置：

```text
SEMANTIC_MAP_MIN_OBJECT_CONFIDENCE=0.35
```

规则：

1. 所有检测仍保留在逐帧原始事件中。
2. 只有置信度为有限数、位于 `[0, 1]` 且 `>= 0.35` 的观测，才允许进入 `SemanticObjectMap`。
3. `purple`、`sparkle` 等纯颜色/属性词，以及 `corner`、`floor`、`wall` 等不应画三维物体框的背景/区域词，不进入三维物体实体图。
4. `person/dog/cat` 等已有动态物体过滤逻辑继续保留。
5. 过滤后的列表必须同时用于 `update_with_associations()`、`association_by_index` 和后续 `semantic_object_localized` 发布，避免下标错位。

`0.35` 与当前 `SAM2_MIN_BOX_SCORE` 对齐，含义是：低于该值的高召回候选可以用于目标搜索和原始取证，但不具备进入持久三维对象图的最低质量。

### 5.2 WebUI 显示门

建议把当前单一常量改成三个可配置参数：

```text
WEBUI_OBJECT_CONFIRMED_MIN_CONFIDENCE=0.45
WEBUI_OBJECT_TENTATIVE_MIN_CONFIDENCE=0.65
WEBUI_OBJECT_CONFIRM_MIN_OBSERVATIONS=2
```

普通物体满足以下任一条件才显示：

```text
A. status == CONFIRMED
   AND observation_count >= 2
   AND aggregate_confidence >= 0.45

B. status == TENTATIVE
   AND aggregate_confidence >= 0.65
```

此外还必须同时满足：

- `map_xyz` 合法；
- `label_zh` 是非空中文显示名；
- 类别/标签不在非物体阻止列表；
- 若绘制 AABB，`box_size` 必须是三个有限正数并通过合理尺寸上限检查；无合法 `box_size` 时只允许按既有逻辑画点，不能伪造框尺寸。

明确通过视觉复核的目标可以单独放行，但必须带明确字段，例如 `target_verified=true`，并使用不同颜色显示。原始检测候选不得自动获得此例外。

### 5.3 用最新真机数据做预估

按上述显示规则回放当前历史事件，在尚未重新计算聚合置信度的兼容模式下：

- 41 个持久 ID 中，现有逻辑显示 11 个；
- 组合门限首先收敛到约 6 个；
- 再排除 `purple` 和 `floor` 这类非独立物体后，预计保留约 4 个：办公椅、垃圾桶/容器、桶、黑色底座；
- `speaker=0.395` 即使出现 5 次，也因低于确认物体显示门限 `0.45` 而不显示；其原始记录仍保留。

该预估只是对现有历史字段的回放结果。新代码启用平均/EMA 聚合后，应以新一轮真机输出为最终验收依据。

## 6. 分文件实施步骤

### 阶段 A：建立唯一的中文显示名解析器

修改 `app/detectors/vocabulary.py`：

1. 扩充本轮实际命中的词：

```text
bin -> 垃圾桶或容器（结合 RAM++ 对应 tags_zh 决定）
barrel -> 桶
stool -> 凳子
lid -> 盖子
hook -> 挂钩
curtain -> 窗帘
speaker -> 音箱
plug -> 插头
```

2. 扩充 RAM 场景词阻止列表：至少加入纯颜色/属性词 `purple`、视觉效果词 `sparkle`、画面区域词 `corner`。阻止列表必须只针对 RAM 场景扩词，不得误杀目标画像中的颜色属性。
3. 新增唯一入口，例如：

```python
resolve_label_zh(raw_label, *, runtime_overrides=None, fallback="未分类物体")
```

解析优先级必须是：

```text
明确目标画像中文名
  > RAM++ 同次返回的 en -> zh 配对
  > 静态 TERM_ZH
  > 原文本身已经包含中文
  > 中文安全兜底“未分类物体”
```

4. 不允许未知英文作为 `label_zh` 的最终值。

### 阶段 B：保住 RAM++ 已经提供的中文标签

修改 `app/detectors/grounded_sam_subprocess.py`：

1. `discover_scene_terms()` 解析 worker 同时返回的 `tags_en/tags_zh`。
2. 对齐过滤后的英文 term，维护当前 detector 实例的 `en -> zh` 映射。
3. `_to_detected_object()` 生成 `DetectedObject` 时使用该映射，而不是只查静态词典。
4. `discover_scene_terms()` 对外仍可返回现有 `list[str]` 英文接口，避免破坏 GroundingDINO prompt；中文映射保存在 detector 内部即可。
5. 对 en/zh 数量不一致、空中文、重复英文写单元测试；不能靠 `zip()` 静默截断后无记录。

修改 `scripts/go2w/run_autonomous_loop.py::_gsam_to_dict()`：

- 透传 `label`、`label_zh`、`category`、`source_prompt_term`、`score`、bbox 和 mask 字段；
- 原始英文不能覆盖 `label_zh`。

修改 `scripts/go2w/run_semantic_exploration.py::analyze_semantic()`：

- 把 `item["category"] = "object"` 改为只在缺失时补默认值；
- 保留 detector 已给出的中文名与类别。

### 阶段 C：标签和类别贯穿三维定位与持久实体

修改以下数据结构与序列化函数：

- `app/perception/depth_object_localizer.py::ObjectSpatialObservation`
- `app/spatial/semantic_object_map.py::SemanticObjectEntry`

要求：

1. `label` 和 `label_zh` 分字段保存；实体硬关联仍使用稳定的规范标签，不使用显示兜底词。
2. `category` 贯穿 localizer、entity map、`to_dict()` 和 `semantic_object_localized` 事件。
3. 合并实体时只在新值明确有效时更新 `label_zh/category`。
4. 不同英文未知类别即使都显示为“未分类物体”，也不能因此被当作同一语义类别合并。
5. 历史/测试构造器缺少新字段时提供兼容默认值，避免一次性破坏所有调用点。

### 阶段 D：在持久地图入口过滤低质量观测

修改 `app/config.py` 和 `.env.example`：

- 增加 `SEMANTIC_MAP_MIN_OBJECT_CONFIDENCE=0.35`；
- 做 `[0, 1]` 范围校验，并在启动配置日志中打印实际生效值。

修改 `scripts/go2w/run_semantic_exploration.py`：

1. `localized` 仍保留完整结果，用于逐帧原始观测事件。
2. 新建明确命名的 `persistent_candidates`，依次执行：动态物体过滤、非物体类别过滤、有限数校验、最低置信度过滤。
3. `SemanticObjectMap.update_with_associations()`、实体事件发布和 `association_by_index` 必须全部基于同一份 `persistent_candidates`。
4. 写结构化统计事件，例如：

```json
{
  "event": "semantic_object_ingest_filter",
  "input": 20,
  "kept": 4,
  "dropped": {
    "low_confidence": 12,
    "non_object_label": 3,
    "invalid_score": 1
  }
}
```

不得原地改完 `localized` 后又用旧索引表；当前代码已有专门注释警告这会导致 persistent ID 串物体。

### 阶段 E：修正实体置信度聚合

修改 `app/spatial/semantic_object_map.py`：

1. 停止用历史最大值作为唯一 `confidence`。
2. 增加 `confidence_max` 和有效观测计数。
3. `confidence` 改为累计平均或有界 EMA。建议优先累计平均，行为最容易测试和解释；若采用 EMA，必须在代码和测试中固定系数。
4. `CONFIRMED` 仍表示多帧/多地图观测确认，但不能替代显示置信度门限。
5. 非有限数、负数和大于 1 的分数不得进入聚合。

建议累计平均公式：

```text
new_mean = (old_mean * old_count + new_score) / (old_count + 1)
```

历史最大值单独写入 `confidence_max`，只用于调试。

### 阶段 F：WebUI 快照层执行最终显示门

修改 `scripts/go2w/webui_map_snapshot_writer.py`：

1. 删除或弃用写死的单一 `MIN_OBJECT_CONFIDENCE`，改为 ROS 参数：

```text
confirmed_object_min_confidence=0.45
tentative_object_min_confidence=0.65
object_confirm_min_observations=2
```

2. 把对象筛选提取为无 ROS 依赖的纯函数，便于 pytest 直接覆盖。
3. 去重后使用“最新事件 + 聚合字段”判定，不得只看任意一次历史高分。
4. 快照对象建议输出：

```json
{
  "label_zh": "音箱",
  "raw_label": "speaker",
  "confidence": 0.58,
  "confidence_max": 0.82,
  "observation_count": 3,
  "status": "CONFIRMED",
  "x": 1.0,
  "y": 2.0,
  "z": 0.5,
  "size": [0.3, 0.2, 0.4]
}
```

5. 为兼容历史事件，缺少 `label_zh/status` 时调用统一解析器，并以 `observation_count` 推导兼容状态；不得直接把英文送前端。
6. 在快照元数据加入过滤统计，例如 `object_filter_stats`，至少包含输入数、显示数和各原因丢弃数。
7. 保留当前“最新 events.jsonl 胜出”和地图 bounds 过滤逻辑，不能在本次整改中回退。

修改 `scripts/go2w/start_manual_web_demo.sh`：

- 如需从环境变量覆盖上述 ROS 参数，在此显式传参；未配置时使用推荐默认值。

### 阶段 G：前端只渲染中文显示字段

修改 `app/manual_web_demo/static/slam_map_3d.js`：

1. `drawObjectBox()` 和 `drawObjectDot()` 只取 `item.label_zh`。
2. 缺失时显示中文兜底“未分类物体”，不能回退到 `raw_label`。
3. 原始英文可放入调试信息或浏览器开发者数据中，但不画在 canvas 上。
4. 置信度继续保留两位小数；建议把确认状态用颜色区分，但不作为本次强制项。
5. 页面状态栏显示“物体框 N 个 / 已过滤 M 个”，便于真机现场确认门限确实生效。
