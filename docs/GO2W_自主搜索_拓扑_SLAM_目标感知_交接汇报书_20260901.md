## 1. 交接摘要

本轮工作针对计划书中提出的四类核心问题进行了完整的代码整改和现场联调：

1. 原地旋转导致 `pslam_odom` 漂移、三维点云重影，并错误创建新 Place；
2. 拓扑图退化成以 `P1` 为中心的 `OBSERVED_FROM` 星型图，缺少稳定的
   OBJECT↔OBJECT 关系；
3. 目标检测只有二值结果，疑似目标可能直接触发运动；
4. WebUI、真实相机/VLM、运动控制、语义搜索和三维地图没有形成可观测的闭环。

目前已经形成可运行的链路：

```text
自然语言任务
    ↓
WebUI / search API
    ↓
真实 D435 HTTP 图像 → SiliconFlow VLM
    ↓
ABSENT / POSSIBLE / PRESENT 目标门控
    ↓
停稳观测 → 语义拓扑 / PlaceGraph / 规划
    ↓
正式 /go2w/motion action（受安全门保护）
    ↓
动作后停稳、读回 odom、重新观测
    ↓
plain_slam pslam_odom → display-only 3D map relay → WebUI 三维界面
```

最近一次 WebUI 真机受控会话中，3 个真实原地旋转动作均成功，实测角度约为
`+28.544° / -28.635° / +28.547°`；会话在明确的 cycle/time budget 边界结束，
没有运动失败，也没有前进。结束时机器人已停止、无运动 goal 在途、错误码为 0，

## 3. 已完成的工作

### 3.1 代码整改

#### A. IMU 时间戳和异常数据

- 新增 `imu_timestamp_aligner.py`，保留真实传感器时间，处理时间回退、重复和异常
  间隔；
- 修正 `imu_fallback_adapter.py`，不再无条件使用 callback receive time 冒充 sensor time；
- 静止采样中获得 15,024 条 IMU，backward/duplicate 均为 0，时间间隔 median 约
  `4.484 ms`、p95 约 `5.027 ms`。

#### B. LIO pose validator 与三维地图保护

- 新增 `app/spatial/spatial_pose_validator.py`；
- 增加 wheel-vs-pslam 平移一致性检查；
- 旋转时若 wheel 平移很小但 pslam 出现异常平移，拒绝该 pose；
- 3D accumulator 保存 last-good pose/cloud，`DEGRADED` 或 `INVALID` 时冻结，不让坏
  `map_3d` 覆盖好地图；
- 增加 `motion_active`、`motion_odom_seen`、`lio_pose_valid`、`mapping_health`、
  `dropped_scans` 等可观测字段。

#### C. PlaceGraph 和 LOCAL_SCAN

- Place 迁移改为依据独立 wheel/motion observed displacement，而不是直接相信 pslam
  平移；
- 原地转向保持当前 Place，不创建 `P2/P3/...`；
- 真平移才允许生成新的 Place/MOVED_TO 证据；
- local scan 状态绑定 canonical `current_place_id`，使用实际 yaw/sector；
- 增加同方向死循环和有限扫描保护；
- planner、local scan、semantic map、WebUI 都从同一个 current Place 投影读取。

#### D. 目标三态和抢占

- 新增 `app/perception/target_state.py`，统一 `ABSENT / POSSIBLE / PRESENT`；
- `POSSIBLE` 不能直接确认目标，也不能触发运动；
- 必须停稳并获取 fresh frame/crop 后再次验证；
- 只有有视觉证据、有效目标框/匹配和达到阈值时才升级为 `PRESENT`；
- 目标抢占期间 `motion_steps` 保持不变。

#### E. OBJECT 拓扑

- 新增 `geometric_relation_extractor.py`；
- 使用 frame object identity → persistent object identity，不把 label 直接当 identity；
- RGB-D Quick 路径可产生 `near / above / below / left_of / right_of` 等基础关系；
- WebUI 将 Object topology 作为主信息之一，不再让 `OBSERVED_FROM` 淹没真实关系。

#### F. WebUI session、worker 和 Full Semantic

- terminal session 与 live topology 分离；
- WebUI 重启后不会把旧 terminal graph 冒充为当前 live graph；
- 新 session 在第一帧观测前保持空 live graph，第一帧后才创建 `P1`；
- worker 启停、归档、异常退出和 stale pidfile 均有处理；
- Full Semantic 作为后台增强器，timeout/error 会记录错误但不打断主搜索，也不会覆盖
  最近一次成功结果。

#### G. 运动控制和传感器采集链

- 新增 SDK 只读 sport state capture 和本地 ROS relay；
- 新增 network lowstate capture 和本地可靠 relay；
- 新增 local motion gateway 与 network motion proxy；
- action 结束后读取 wheel q/dq 计算实际距离；
- 保留 `/go2w/arm`、`/go2w/emergency_stop` 和运动租约/心跳链路；
- 不使用底层关节控制或 lowcmd 绕过控制栈。

#### H. 相机、跨主机和启动脚本

- 新增机器人端 JPEG capture fallback；
- 增加紧凑 `/go2w/slam/web_scan` relay，避免大 PointCloud2 直接跨主机压垮远端 Python
  worker；
- 修正 VLM HTTP proxy、Python interpreter、`PYTHONPATH` 和 `scripts/go2w` 优先级；
- 启动脚本检查唯一 odom publisher、唯一 WebUI 实例、相机/VLM/mapping 依赖和安全环境。

### 阶段 2：WebUI 正向目标搜索验收

1. 使用完整任务句，例如“寻找办公椅”或“寻找蓝色垃圾桶”；
2. 首次只启用 dry-run，验证真实 D435/VLM、目标状态、拓扑和归档；
3. 确认目标为 `POSSIBLE` 时没有新增 motion step；
4. 确认 `PRESENT` 只在 fresh frame/crop 复核后出现；
5. 再在操作员监督下做 `turn_only` ≤30° 验收；
6. 检查 Place 始终为一个 canonical ID，且 3D map 没有旋转扇形重影；
7. 最后使用 UI 的 stop 操作结束任务，并确认 `motion_in_flight=false`。

### 阶段 3：WebUI 短距离平移验收

在阶段 2 连续通过后，才做很小的前进距离。需要记录：

- action result 是否 success；
- wheel/fused odom 实测距离；
- yaw 偏差和结束 stationary；
- 是否只创建一个新的 Place；
- 新 Place 后原地旋转是否仍保持该 Place；
- 地图点云是否由有效 pose 持续累积。

该阶段必须单独归档，不应拿 CLI D 阶段结果替代 WebUI 平移证据。

### 阶段 4：外参、deskew 与 LIO 专项标定

建议采集以下数据并离线分析：

1. 机器人静止 60–120 s；
2. 低速直行并停止；
3. 原地左右旋转各若干次；
4. 经过有平面、边缘和已知尺寸物体的场景；
5. 同步保存 Pandar、IMU、wheel odom、`pslam_odom`、`/go2w/odom/fused` 和相机时间戳。

输出应至少包含：时间偏移、旋转/平移外参、deskew 前后残差、rotation-only 平移漂移、
静止点云重合度、运动期坏帧拒绝率。只有数据验收通过后，才考虑更新 extrinsic status。
