# Go2-W 实体遥控器主动建图 + 周期物体识别落图 MVP 实施计划

> 日期：2026-09-18  
> 遥控方式定义：本文中的“遥控”只指 **Unitree 实体遥控器**。机器狗的移动由官方遥控器和机身底层控制器完成，不使用网页 WASD/QE，不通过本项目发送运动指令。  
> 目标：操作员拿实体遥控器驾驶 Go2-W 时，项目在后台持续运行 `plain_slam` 建图；每隔一段时间用 D435 做一次物体识别，并把物体转换到 `pslam_map` 坐标系后标在现有三维地图上。  
> 实施原则：做一个能用的 MVP，最大限度复用现有 SLAM、检测、深度定位、语义地图和 WebUI；不重写算法，不引入自主搜索，不铺大量测试。

---

## 1. 最终使用方式

实现完成后，控制主机上只需运行：

```bash
cd /home/mxt/robotscene
bash scripts/go2w/start_remote_control_mapping.sh
```

然后：

1. 操作员打开 Unitree 实体遥控器并连接机器狗。
2. 操作员使用实体遥控器让机器狗起立、前进、后退和转向。
3. 软件不参与运动控制，只读取 LiDAR、IMU、SLAM、TF 和 D435 RGB-D。
4. `plain_slam` 随机器狗的实际运动持续扩展三维地图。
5. 后台按“位移、转角或最长等待时间”高频保留 RGB-D 关键帧：默认每移动约 0.75 m、转过约 15°，或距离上一关键帧满 1 秒时留一帧。
6. GroundedSAM 单实例连续处理关键帧，处理完一帧后立即取下一帧，不再人为等待 5 秒。
7. 识别成功的静态物体显示在现有三维地图页面中；GPU 忙时允许显示比现场运动滞后几秒，但不能因此丢掉整段路径。
8. 检测失败或模型暂时繁忙时，仅跳过当前帧，不影响实体遥控和 SLAM。

停止软件：

```bash
bash scripts/go2w/stop_remote_control_mapping.sh
```

此启动流程中不需要、也不允许使用：

```text
--enable-motion
GO2W_AREA_CLEARED=I_HAVE_CLEARED_THE_AREA
网页“启用键盘控制”按钮
WASD/QE
```

这些属于项目的软件运动链，与本功能无关。现场仍必须由操作员负责清场并随时握住实体遥控器急停。

## 2. 对现有代码的正确理解

### 2.1 实体遥控器运动和项目软件运动是两条不同链路

实体遥控器路径大致是：

```text
Unitree 实体遥控器
        │
        ▼
机器狗 wheeled_sport / 底层控制器
        │
        ▼
电机和轮腿执行机构
```

项目的软件运动路径是：

```text
WebUI WASD/QE
  -> ManualDriveController
  -> manual_web_demo_ros_worker.py
  -> /go2w/motion Action
  -> Unitree 运动服务
```

本功能只使用第一条路径。第二条路径不能被启动、修改或作为功能依赖。

仓库中的 `unitree_go2w_control/scripts/monitor_remote_keys.py` 可以只读订阅
`/wirelesscontroller` 和 `/wirelesscontroller_unprocessed`，说明实体遥控器状态能够被观察；但主动建图并不需要理解摇杆值，也不需要把遥控器消息转换成速度指令。

只要机器狗移动，LiDAR 和 IMU 数据就会变化，SLAM 会根据传感器数据更新地图。SLAM 不关心这次运动是自主搜索、命令行还是实体遥控器造成的。

### 2.2 建图链本来就是独立的

现有建图链为：

```text
PandarXT-16 /hesai/pandarxt16/points_raw
                  +
Unitree IMU /utlidar/imu
                  │
                  ▼
scripts/go2w/start_plain_slam_mapping.sh
                  │
                  ├── /go2w/slam/map_3d
                  ├── /go2w/slam/map_2d
                  ├── /go2w/slam/odom_base
                  ├── /go2w/slam/ready
                  └── /tf: pslam_map -> pslam_odom
```

`start_plain_slam_mapping.sh` 的文件头已经明确：它只启动建图，不启动运动，不修改 `/go2w/odom/fused`，不取得 `/go2w/motion` 控制权。

因此“以前只能自主搜索时建图”主要是启动编排问题，不是 SLAM 算法限制。自主搜索启动器碰巧把 SLAM、感知和 WebUI 一起启动了；实体遥控时缺少一条只启动感知与建图的独立入口。

### 2.3 现有自主搜索已经具备完整的物体落图能力

`scripts/go2w/run_semantic_exploration.py` 中已经有可直接复用的组件：

| 现有组件 | 用途 |
| --- | --- |
| `RealSenseHTTPRGBDSource` | 从 D435 HTTP 服务取得同一次采集的 RGB、depth、intrinsics 和时间戳 |
| `GroundedSAMSubprocessDetector` | RAM++ 生成标签，GroundingDINO 检框，SAM2 生成 mask |
| `DepthObjectLocalizer` | 根据 mask/框和深度计算物体 `camera_xyz`、尺寸及有效深度统计 |
| `PlainSlamSpatialProvider` | 缓存 SLAM odom、TF、二维地图，并按拍摄时间把相机坐标转换到 `pslam_map` |
| `SemanticObjectMap` | 按类别和空间距离合并多帧观测，避免同一物体反复新增 |
| `drop_dynamic_objects` | 排除人、动物等不适合永久标图的动态物体 |
| `filter_persistent_observations` | 过滤明显不适合持久化的观测 |

自主搜索当前会写出 `semantic_frame_objects_localized` 和
`semantic_object_localized` 事件。`webui_map_snapshot_writer.py` 已经能够读取这些事件，`slam_map_3d.js` 已经能在三维点云上绘制物体名称、点位和三维框。

MVP 不需要新设计协议，也不需要把自主搜索循环搬过来。只需要一个独立的“实体遥控语义建图侧车”，周期执行现有感知流水线。

### 2.4 手动网页里的 SiliconFlow 识别不能直接用于落图

`app/manual_web_demo/scene_object_analyzer.py` 当前每隔约 5 秒可以做场景识别，但输出主要是：

```text
name / count / position / confidence
```

它没有稳定的 bbox/mask、同帧深度、`camera_xyz`、拍摄时刻位姿和 `map_xyz`，所以不能把它的文字位置直接当成地图坐标。

本功能应关闭这条简单 VLM 定时识别，避免与真正的 RGB-D 语义侧车重复耗费 GPU。落图必须复用自主搜索里的 GroundedSAM + depth + timestamped SLAM pose 链路。

### 2.5 WebUI 可以复用，但只能作为只读地图查看器

现有 `/api/slam/map3d` 读取 JSON 快照，前端已经支持物体绘制，因此不应另写地图页面。

不过实体遥控模式下，WebUI 只能负责显示：

- 不默认启用软件控制；
- 不因页面按键向 `/go2w/motion` 发请求；
- 不允许启动自主搜索；
- 不把网页控制是否可用作为建图前提；
- 网页关闭也不能影响实体遥控器。

为避免误操作，建议给现有 Web server 增加一个很小的 `display_only` 配置门。在该模式下所有软件运动入口直接拒绝，页面显示“实体遥控建图：只读”。

## 3. MVP 总体架构

```text
                       运动域（项目完全不写）
┌──────────────────┐
│ Unitree 实体遥控器 │ ─────► wheeled_sport / 底层控制器 ─────► 机器狗运动
└──────────────────┘

                       只读建图域
PandarXT-16 ──┐
              ├────► plain_slam ─────► map_3d / odom_base / TF
Unitree IMU ──┘                              │
                                            │
                       周期语义域           │
D435 RGB-D ─► RAM++/DINO/SAM2 ─► depth 3D ─┤
                                            ▼
                                  camera_xyz -> map_xyz
                                            │
                                            ▼
                                    SemanticObjectMap
                                            │
                                            ▼
                     remote_mapping_events.jsonl
                                            │
                map_3d ─────────────────────┤
                                            ▼
                              webui_map_snapshot_writer.py
                                            │
                                            ▼
                                现有 WebUI 三维地图（只读）
```

必须保持的进程边界：

- `plain_slam`：持续实时运行，不等待检测器。
- `remote_control_semantic_mapping_worker.py`：独立进程；模型加载和推理不能阻塞 SLAM 或 Web server。
- `webui_map_snapshot_writer.py`：只负责把 ROS 地图和语义事件合成快照。
- FastAPI/WebUI：只读显示，不承担检测，不承担运动。

## 4. 严格范围

### 4.1 本次要做

- 新增实体遥控建图的一键启动和停止脚本。
- 启动或复用唯一一套 `plain_slam`。
- 新增一个独立的周期语义建图 worker。
- 按位移、转角和最长时间生成 RGB-D 关键帧，避免高速遥控时出现 5 秒视觉空洞。
- 使用一个有界关键帧队列，检测器单实例连续消费，不并行加载多套模型。
- 使用拍摄时刻的 SLAM 位姿进行坐标变换。
- 复用 `SemanticObjectMap` 做简单跨帧去重。
- 复用现有三维地图快照和 WebUI 绘制物体。
- 给 WebUI 增加实体遥控模式的只读门，防止误触软件运动。
- 一次运行使用一份新的语义事件文件，不能混入旧自主搜索物体。

### 4.2 本次明确不做

- 不解析实体遥控器摇杆来控制 SLAM。
- 不向 `/wirelesscontroller` 或 `/wirelesscontroller_unprocessed` 发布任何消息。
- 不调用 `/go2w/motion`、`cmd_vel`、arm、stand、Sport API 或急停服务。
- 不启动 `manual_web_demo_ros_worker.py` 的运动用途。
- 不启动自主搜索 worker、frontier、Nav2、PlaceGraph 或目标搜索状态机。
- 不修改 `plain_slam` 算法和参数。
- 不用 `/go2w/odom/fused` 冒充 `pslam_map`。
- 不强制机器狗每 5 秒停车。
- 不做物体编辑、手工拖拽、数据库管理和跨会话地图拼接。
- 不建立大规模测试矩阵，只做静态检查和一次短真机验收。

## 6. 详细实施步骤

### 6.1 新增实体遥控语义建图 worker

新建：

```text
scripts/go2w/remote_control_semantic_mapping_worker.py
```

它是一个纯感知侧车，不应包含任何 motion client、Action client、速度发布器或遥控器发布器。

#### 命令行参数

建议保留最少参数：

```text
--events PATH              本次运行事件文件
--status PATH              当前状态 JSON
--capture-poll-seconds 0.2  检查是否应采关键帧的周期
--keyframe-max-seconds 1.0  静止或慢速时两关键帧的最大时间间隔
--keyframe-distance-m 0.75  行进达到该距离就保留关键帧
--keyframe-yaw-deg 15       转向达到该角度就保留关键帧
--queue-size 20             待推理关键帧队列上限
--rgbd-base-url URL        D435 HTTP 服务地址
--once                     只跑一轮，供无运动烟雾检查
```

模型和阈值继续读取项目现有配置，不再创建一套重复参数。

#### 初始化

按现有 `run_semantic_exploration.py` 的构造方式复用：

```python
RealSenseHTTPRGBDSource
GroundedSAMSubprocessDetector
DepthObjectLocalizer
PlainSlamSpatialProvider
SemanticObjectMap
```

还要复用现有的：

```python
drop_dynamic_objects
filter_persistent_observations
```

不要 import 或实例化探索规划器、运动执行器、frontier、PlaceGraph 和搜索状态机。

#### 采帧与推理解耦

不能把“多久拍一帧”和“模型多久跑完一帧”写成同一个串行 `sleep(5)` 循环。仓库已有基准记录显示 GroundedSAM 常驻后 warm latency 约 **1.858 秒**，首次 cold latency 约 **8.554 秒**；固定 5 秒再开始下一轮会把实际观察间隔进一步放大。

worker 内部使用两个轻量执行单元：

1. **关键帧采集器**：持续 spin ROS 位姿缓存，并约每 0.2 秒判断一次是否需要采帧。
2. **单实例推理消费者**：始终只有一个 GroundedSAM 调用，上一帧完成后立即取下一帧。

关键帧满足以下任意条件就采集：

```text
距上一关键帧的 pslam 里程 >= 0.75 m
或累计 yaw 变化 >= 15°
或距上一关键帧时间 >= 1.0 s
```

第一次获得有效 RGB-D 和 SLAM 位姿时立即采一帧。三个阈值均做成参数，但上述值作为 MVP 默认值。

每个队列元素必须一起保存：

```text
RGB
与 RGB 对齐的 depth
intrinsics
frame_id
capture_timestamp
采帧时的 robot pose / mapping session id（用于诊断）
```

默认队列上限为 20。队列满时，优先删掉与相邻帧位置和朝向最接近的冗余帧，不要无条件“只留最新帧”；如果 20 帧都代表不同位置，再丢最旧帧并增加 `dropped_keyframes` 计数。以 0.75 m 间距计算，20 帧能覆盖约 15 m 的高速度路段，足以处理用户提出的“5 秒接近 10 m”场景。

这套设计保证的是**路径视觉覆盖**，不是所有物体都实时出现。GPU 推理速度不足时，地图上的物体标记会滞后；但已经采下来的中间关键帧仍会随后被处理，不会因为检测器忙就完全错过整段路。

#### 每个关键帧的推理流程

1. 从队列取出下一关键帧，不重新抓取 RGB 或 depth。
2. RAM++ 生成开放词表候选标签。
3. GroundingDINO 检测候选物体框。
4. SAM2 为框生成 mask。
5. 删除人、动物等动态类别。
6. `DepthObjectLocalizer` 使用关键帧内的 depth、intrinsics 和 mask 计算 `camera_xyz`、尺寸与深度质量。
7. 对无有效深度、深度样本太少、置信度太低和尺寸明显异常的观测直接跳过。
8. 调用 `PlainSlamSpatialProvider.camera_point_to_map(camera_xyz, capture_timestamp)`。
9. 变换失败时不得使用最新位姿硬凑；当前观测不落图，记录原因后继续下一帧。
10. 生成包含 `map_xyz` 和 map-frame 3D bbox 的 localized observation。
11. 调用 `SemanticObjectMap.update_with_associations(...)` 合并同一实体。
12. 追加现有格式的 `semantic_frame_objects_localized` 事件。
13. 对新增或更新的持久实体追加 `semantic_object_localized` 事件。
14. 原子更新状态文件，然后立即处理队列中的下一帧；队列为空时才等待。

#### 不要因机器狗正在运动而发停止命令

实体遥控器始终由人控制。侧车绝不为了拍照调用 stop。

MVP 可以在运动中采帧。若图像模糊或深度质量不好，由质量门丢掉这一轮即可。可选地读取 `/go2w/slam/odom_base` 的速度，当角速度或线速度过高时写入 `skipped_robot_moving_fast`，但只能“跳过识别”，不能干涉运动。

#### 状态文件

`outputs/remote_control_mapping/runtime/status.json` 至少包含：

```json
{
  "state": "waiting|loading|running|degraded|stopped",
  "last_attempt_at": null,
  "last_success_at": null,
  "last_frame_id": null,
  "last_detection_count": 0,
  "last_localized_count": 0,
  "persistent_object_count": 0,
  "queue_depth": 0,
  "captured_keyframes": 0,
  "dropped_keyframes": 0,
  "inference_latency_seconds": null,
  "slam_ready": false,
  "last_error": null
}
```

使用临时文件加 `os.replace()` 原子写入，避免页面或排障脚本读到半个 JSON。

#### 错误隔离

- 单帧 RGB-D 失败：记录并等下一轮。
- 一轮检测异常：记录并等下一轮。
- TF 暂时缺失：本轮不落图。
- GPU OOM：清理当前推理资源，进入 degraded，降低频率重试；不能退出 SLAM。
- 连续失败：worker 可以保持存活并定时重试。
- SIGTERM：完成当前轻量清理后退出，关闭 detector subprocess 和 ROS node。

### 6.2 新增一键启动器

新建：

```text
scripts/go2w/start_remote_control_mapping.sh
```

启动顺序必须是：

#### A. 环境与传感器预检

1. `source scripts/go2w/setup_environment.sh`。
2. 检查 Pandar 点云是否有 publisher 和实际数据。
3. 检查 `/utlidar/imu`；没有时给出明确降级告警。
4. 检查 D435 HTTP RGB-D 服务是否能返回有效帧。
5. 检查模型和 Python 环境；缺少时启动失败并指出日志。

这一步只读检查，不查询或修改运动控制权。

#### B. 启动或复用 plain_slam

判定以下话题是否已有唯一、健康的发布者：

```text
/go2w/slam/map_3d
/go2w/slam/odom_base
/go2w/slam/ready
```

- 如果已有健康 `plain_slam`，直接复用，不启动第二套。
- 如果没有，调用现有 `scripts/go2w/start_plain_slam_mapping.sh`。
- 启动器记录一个 `slam_started_by_remote_mapping` ownership marker。
- 在有限时间内等待 ready、odom 和 map；超时则停止本次新建的侧车并明确报错。
- 不允许两个 `lio_3d_node`、两个 `slam_3d_node` 或两个 Pandar driver 同时存在。

注意：`start_plain_slam_mapping.sh` 会创建新的 SLAM session 并清理它自己的旧缓存。不要在语义 worker 中重复做这件事。

#### C. 创建本次语义会话

建议路径：

```text
outputs/remote_control_mapping/runtime/events.jsonl
outputs/remote_control_mapping/runtime/status.json
outputs/remote_control_mapping/runtime/semantic_mapper.pid
outputs/remote_control_mapping/runtime/snapshot_writer.pid
outputs/remote_control_mapping/runtime/web.pid
outputs/remote_control_mapping/logs/semantic_mapper.log
outputs/remote_control_mapping/logs/snapshot_writer.log
outputs/remote_control_mapping/logs/web_server.log
```

每次启动前把上一份 `events.jsonl` 改名为带时间戳的归档文件，再创建空的新文件。原因是 `pslam_map` 在新 SLAM session 中可能重新定义，绝不能把旧坐标系物体混入新地图。

#### D. 启动语义侧车

示意：

```bash
setsid <具备项目模型依赖和 rclpy 的 Python> \
  scripts/go2w/remote_control_semantic_mapping_worker.py \
  --events outputs/remote_control_mapping/runtime/events.jsonl \
  --status outputs/remote_control_mapping/runtime/status.json \
  --capture-poll-seconds "${REMOTE_MAPPING_CAPTURE_POLL_SECONDS:-0.2}" \
  --keyframe-max-seconds "${REMOTE_MAPPING_KEYFRAME_MAX_SECONDS:-1.0}" \
  --keyframe-distance-m "${REMOTE_MAPPING_KEYFRAME_DISTANCE_M:-0.75}" \
  --keyframe-yaw-deg "${REMOTE_MAPPING_KEYFRAME_YAW_DEG:-15}" \
  --queue-size "${REMOTE_MAPPING_QUEUE_SIZE:-20}" \
  --rgbd-base-url "${REMOTE_MAPPING_RGBD_BASE_URL:-http://192.168.123.18:8080}" \
  > outputs/remote_control_mapping/logs/semantic_mapper.log 2>&1 &
```

启动后检查 PID 存活，并等待状态到 `running` 或给出 `degraded` 原因。

#### E. 启动地图快照写入器

复用 `webui_map_snapshot_writer.py`，关键参数为：

```text
map_topic=/go2w/slam/map_3d
odom_topic=/go2w/slam/odom_base
objects_events=<当前 remote events.jsonl>
objects_glob=""
period_s=1.0
```

`objects_glob` 必须置空。本模式唯一的物体源是本次实体遥控会话，不能从
`outputs/live_runs/search_*/events.jsonl` 猜一份旧自主搜索结果。

快照可以继续写到现有 WebUI 默认路径：

```text
outputs/autonomous_search/runtime/slam_map_3d.json
```

这样能直接复用 `/api/slam/map3d` 和 `slam_map_3d.js`，无需改地图协议。

#### F. 以只读模式启动现有 WebUI

启动 FastAPI 前设置：

```bash
export MANUAL_DEMO_DISPLAY_ONLY=1
export MANUAL_DEMO_CONTROL_ENABLED=0
export MANUAL_DEMO_LLM_ENABLED=0
```

然后启动现有：

```text
uvicorn app.manual_web_demo.web_server:app
```

在 `DISPLAY_ONLY=1` 时：

- `/api/control/enable` 返回 403 和清晰原因；
- 所有控制 WebSocket 输入被忽略或拒绝；
- `/api/search/start` 不得启动自主搜索；
- 后端不发送 stop、estop、arm 或 motion 请求；
- 前端隐藏或禁用 WASD/QE 控制区，显示“实体遥控器模式，网页只读”；
- 地图、相机画面和状态查看仍正常。

如果把 Web server 改成完全不启动 ROS motion worker 需要较多重构，MVP 可以保留只读状态订阅，但必须确保 `DISPLAY_ONLY` 下没有任何写运动路径。优先在 API/WS 入口做统一硬门，不要散落很多条件判断。

### 6.3 新增停止脚本

新建：

```text
scripts/go2w/stop_remote_control_mapping.sh
```

按顺序停止：

1. 只读 Web server。
2. `webui_map_snapshot_writer.py`。
3. `remote_control_semantic_mapping_worker.py`。
4. 如果存在 ownership marker，说明本模式启动了 `plain_slam`，再调用 `stop_plain_slam_mapping.sh`。
5. 如果没有 marker，说明 SLAM 是外部已有进程，只打印“reused, left running”，不要停止。

对每个 PID：

- 先读 `/proc/<pid>/cmdline` 校验确实是目标进程；
- 先发 SIGTERM 并短暂等待；
- 必要时再 SIGKILL；
- 删除对应 PID 文件。

禁止使用：

```text
pkill ros2
killall python
宽泛的 pkill -f python
任何 Unitree 运动停止 API
```

停止软件不会停止机器狗运动。操作员必须先用实体遥控器停稳机器狗，再运行停止脚本。

## 7. 事件合同

### 7.1 单帧定位事件

沿用现有事件类型：

```json
{
  "type": "semantic_frame_objects_localized",
  "timestamp": "2026-09-18T12:00:00+08:00",
  "data": {
    "source": "remote_control_mapping",
    "frame_id": "d435_...",
    "capture_timestamp": 0.0,
    "map_frame": "pslam_map",
    "objects": [
      {
        "label": "chair",
        "confidence": 0.82,
        "camera_xyz": [1.2, -0.1, 0.3],
        "map_xyz": [3.4, 1.7, 0.3],
        "bbox_3d": {},
        "depth_valid_ratio": 0.76
      }
    ]
  }
}
```

字段名以仓库当前 writer/reader 的真实合同为准，不要为了示例强行改 schema。

### 7.2 持久实体事件

继续输出 `semantic_object_localized`，并至少保留 WebUI 现有读取逻辑所需字段：

```text
object_id
label/name
confidence
observation_count
map_xyz
bbox_3d 或 dimensions
state（tentative/confirmed，如现有实现提供）
last_seen_at
```

### 7.3 去重原则

- 不能只按 label 合并；两个相距很远的 chair 必须是两个实体。
- 同类别且空间距离在现有 merge radius 内时更新已有实体。
- 同一帧明显重叠的重复框先做现有 NMS/association。
- 动态类别不进入持久地图。
- 单次低置信观测按现有 tentative/confirmed 显示门处理，不要为 MVP 发明复杂追踪器。

## 8. 坐标、时间与 SLAM 会话要求

### 8.1 唯一合法地图坐标系

持久物体坐标必须满足：

```text
map_frame == pslam_map
```

禁止把以下坐标直接写成地图坐标：

```text
camera_xyz
pslam_odom
/go2w/odom/fused
base_link 当前局部坐标
二维图像中的 left/right/center
```

### 8.2 必须使用拍摄时刻位姿

正确公式：

```text
p_map = T_pslam_map_camera(capture_timestamp) * p_camera
```

不能在十几秒推理完成后取“最新位姿”，否则实体遥控器已经把机器狗开到别处，物体会被标错位置。

### 8.3 同帧 RGB-D

检测使用的 RGB 与定位使用的 depth 必须属于同一组采集结果。不能先拉一张 RGB，推理完成后再拉一张新 depth。

### 8.4 SLAM session 不能混用

`start_plain_slam_mapping.sh` 重启后，`pslam_map` 原点可能改变。因此：

- 新 session 必须清空当前显示中的旧物体；
- 旧 events 只归档，不继续作为当前物体源；
- worker 发现 mapping session 变化时，最简单做法是清空内存中的 `SemanticObjectMap` 并开始新 events，或明确退出让启动器重启；
- MVP 不做跨 session 坐标对齐。

## 9. 安全与稳定性要求

### 9.1 软件必须对运动只读

可用一个简单静态检查确认新文件没有运动输出：

```bash
rg -n "/go2w/motion|cmd_vel|request_arm|request_stop|request_estop|SportClient|ChannelPublisher" \
  scripts/go2w/start_remote_control_mapping.sh \
  scripts/go2w/stop_remote_control_mapping.sh \
  scripts/go2w/remote_control_semantic_mapping_worker.py
```

预期不出现实际调用。注释里的禁止说明可人工忽略。

### 9.2 感知不能阻塞建图

GroundedSAM 模型加载、GPU 推理、D435 超时和 events 写盘都在独立 worker 中。即使该 worker 崩溃：

- 实体遥控器仍然能控制机器狗；
- `plain_slam` 仍继续建图；
- WebUI 至少继续显示点云；
- 启动器/状态页能看到语义 worker degraded 或 exited。

### 9.3 只排关键帧，不重叠推理

允许最多 20 个空间关键帧排队，以覆盖检测器忙碌期间走过的路段；不允许无界积压普通视频帧，也不允许同时启动多个 GroundedSAM 子进程。消费者处理完一帧后立即处理下一帧，不再增加固定 5 秒等待。

### 9.4 实体遥控优先

现场发生任何异常时，操作员直接使用实体遥控器停稳或急停。软件不能假设自己拥有运动控制权，也不能在退出时尝试替操作员发送停止命令。

## 10. 最小检查与真机验收

用户要求“能凑合用即可”，所以只做下面这些，不新增庞大测试集。

### 10.1 静态检查

```bash
python3 -m py_compile scripts/go2w/remote_control_semantic_mapping_worker.py
bash -n scripts/go2w/start_remote_control_mapping.sh
bash -n scripts/go2w/stop_remote_control_mapping.sh
```

再执行第 9.1 节的运动输出搜索。

### 10.2 单轮无运动烟雾检查

机器狗静止、软件不发运动命令：

```bash
<正确 Python> scripts/go2w/remote_control_semantic_mapping_worker.py \
  --once \
  --events /tmp/go2w_remote_mapping_smoke_events.jsonl \
  --status /tmp/go2w_remote_mapping_smoke_status.json
```

只检查：

- 能取得 RGB-D；
- 模型能返回检测结果或合法空结果；
- 有深度的物体能得到 `map_xyz`；
- events JSONL 每行可解析；
- 没有运动调用。

### 10.3 三到五分钟真机验收

全程由操作员持实体遥控器，先清空平整区域。

1. 运行 `start_remote_control_mapping.sh`。
2. 确认 WebUI 显示“实体遥控器模式，网页只读”。
3. 尝试点击网页控制，确认被拒绝且机器狗不动作。
4. 机器狗静止 20 秒，确认地图没有明显自行漂移。
5. 用实体遥控器缓慢前进约 2 米并左右转向。
6. 确认 `/go2w/slam/map_3d` 持续更新，WebUI 中地图范围扩大。
7. 在椅子、桌子、门等明显静态物体附近缓慢经过。
8. 等待至少两到三轮识别，确认 events 出现 `semantic_object_localized`。
9. 确认 WebUI 地图上出现物体标记，位置大致落在对应点云结构附近。
10. 故意让一轮相机识别失败或短暂遮挡，确认实体遥控和 SLAM 不受影响。
11. 先用实体遥控器停稳机器狗，再运行停止脚本。

### 10.4 MVP 通过标准

- [ ] 全程运动由实体遥控器完成，软件没有发送运动命令。
- [ ] 没有启动自主搜索 worker。
- [ ] 遥控前进和转向时三维地图持续扩展。
- [ ] 高速行进时按约 0.75 m/15° 留关键帧，慢速或静止时至少每 1 秒留一帧。
- [ ] GroundedSAM 始终单实例连续消费，队列有界且不会并发加载模型。
- [ ] 至少一个静态物体获得 `pslam_map` 坐标并显示在地图中。
- [ ] 同一个静态物体重复看到时不会无限生成新标记。
- [ ] 识别失败不会中断 SLAM。
- [ ] 新 SLAM session 不显示旧 session 的物体。
- [ ] 停止脚本只结束自己拥有的软件进程。
